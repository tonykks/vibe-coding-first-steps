프로그램을 만들고, 고치고, 내 것으로 보관하기

이 안내서는 ChatGPT Plus를 사용하여 바이브코딩을 시작하는 사람이 강연 중 주요 개념을 확인하고, 귀가 후에도 혼자 Chat·Work·Codex를 선택해 프로그램을 만들 수 있도록 구성했습니다. 사용 환경과 메뉴는 제공 상태에 따라 달라질 수 있습니다.

이 자료의 Chat → Work → Codex 배열은 서비스의 작업 방식을 이해하기 위한 설명 순서이며 필수 사용 순서나 사용자 수준의 등급이 아닙니다.

01. 바이브코딩의 출발점

코드를 잘 쓰는 능력보다 해결할 문제를 설명하고 결과를 검증하는 능력이 중요합니다.

Vibe Coding(바이브코딩)은 목적·조건·업무 절차를 자연어로 전달하고 AI의 도움으로 프로그램을 설계·작성·수정·검증하는 방식입니다. 코드를 모르더라도 시작할 수 있지만, 결과가 정확한지 판단하는 일은 사용자에게 남습니다.

Owner(오너, 최종 책임자)는 무엇을 만들지 결정하고 검증·공개를 승인합니다. MVP(Minimum Viable Product, 최소 기능 제품)는 문제 하나를 해결하는 데 필요한 핵심 기능부터 구현한 첫 버전입니다.

가장 먼저 할 일

  1. 내가 자주 반복하는 일 한 가지를 고릅니다.
  2. 지금 하는 순서와 원하는 결과를 적습니다.
  3. 프로그램이 제대로 작동했는지 확인할 기준을 정합니다.
  4. 작은 MVP부터 만들고 직접 사용한 뒤 수정합니다.

핵심: AI가 업무를 저절로 아는 것이 아니라, 내가 업무의 기준을 알려주고 검증합니다.

02. ChatGPT Plus의 서비스 지도

Chat·Work·Codex는 사용자의 실력에 따른 단계가 아니라 목적이 다른 작업 방식입니다.

작업 방식한 줄 정의바이브코딩에서 주로 하는 일
Chat대화로 생각·요구사항·코드·설명을 다듬는 방식아이디어 정리, 간단한 HTML 코드, 수정 지시 작성
Work여러 단계의 작업과 파일·사이트 등 완성된 결과물을 맡기는 방식파일 제작, 분석, 웹 도구 제작, 결과물 확인
Codex파일·저장소·명령·테스트를 다루는 Coding Agent프로젝트의 코드 작성·수정·실행·테스트·이력 관리

LLM(Large Language Model, 대규모 언어 모델)은 글과 코드를 생성하는 모델이며, Agent(에이전트, 대리 수행 시스템)는 목표를 받아 도구를 사용해 작업하는 체계입니다. Codex는 모델 하나의 이름으로만 이해하기보다 모델과 개발 도구를 활용하는 Coding Agent로 구분합니다.

핵심: 처음 시작하는 사람도 Chat, Work 또는 Codex 중 자신의 목표에 맞는 방식으로 바로 시작할 수 있습니다.

03. 웹사이트와 데스크톱 앱의 차이

Web/Desktop은 접속 방법이고 Cloud/Local은 작업 실행 장소입니다.

구분뜻확인할 점
Web(웹)브라우저에서 chatgpt.com 등을 열어 접속설치 없이 Chat·Work를 이용하고 지원되는 별도 Codex Cloud 경로를 이용
Desktop(데스크톱)PC에 설치한 ChatGPT 앱에서 접속Chat·Work·Codex 메뉴 및 허용된 로컬 폴더 작업
Cloud(클라우드)원격 컴퓨터에서 작업 수행작업 파일과 저장 위치가 내 PC가 아닐 수 있음
Local(로컬)내 컴퓨터에서 파일·명령을 다룸작업 폴더 및 실제 변경 파일 확인

Execution Environment(실행 환경)은 코드가 실제로 실행되는 컴퓨터 또는 작업 공간입니다. 데스크톱 앱을 설치했다고 LLM 자체가 내 PC에서 실행되는 것은 아닙니다. Local 작업도 모델과 필요한 작업 맥락을 네트워크로 주고받을 수 있습니다.

핵심: 모델이 응답을 만드는 곳과 프로그램 파일이 수정되는 곳을 따로 확인합니다.

04. 모델과 추론 용어 이해

LLM의 실행 과정과 문제를 논리적으로 해결하는 능력은 다른 개념입니다.

용어쉬운 설명실제 문맥
Inference(모델 추론 실행)모델에 입력을 보내 출력이 생성되는 계산 과정모델 호출, 응답 시간, 토큰 비용
Reasoning(논리적 추론)여러 조건을 연결해 문제를 분석하고 해결하는 능력·과정오류 원인 분석, 수정 계획 수립
Coding Agent모델과 파일·명령·테스트 도구를 이용하는 개발 수행 시스템Codex로 프로젝트 파일 수정

Inference와 Reasoning은 한국어에서 모두 “추론(推論)”으로 번역되지만 초점이 다릅니다. Reasoning이 필요한 요청도 모델을 실행하는 Inference를 통해 처리됩니다. 모델의 선택 가능 종류와 사고 수준은 계정·화면의 실제 제공 옵션을 확인합니다.

핵심: LLM = 생성·판단을 담당하는 모델, Codex = 모델과 개발 도구를 결합한 코딩 수행 환경.

05. 웹 Chat으로 시작하기

브라우저에서 요구사항을 정리하고 간단한 코드를 만들 수 있습니다.

  1. 브라우저에서 chatgpt.com에 접속해 Plus 계정으로 로그인합니다.
  2. 새 Chat 대화를 시작합니다.
  3. 무엇을 만들지, 입력·처리·출력·검증 기준을 자연어로 설명합니다.
  4. 생성된 코드 또는 파일을 확인하고 실행 방법을 질문합니다.
  5. 필요하면 다운로드하거나 복사해 내 PC에 보관합니다.

요구사항 예시

브라우저에서 실행할 한글 타자 연습 웹앱을 만들고 싶습니다.
사용자가 선택한 글쇠를 20번 입력하게 하고, 오답을 표시하고, 정확도를 계산해 주세요.
먼저 필요한 기능과 이번 버전에서 제외할 기능을 정리해 주세요.
제가 승인하기 전에는 코드를 작성하지 마세요.

Chat의 응답에 코드가 보인다고 곧바로 PC의 프로젝트 폴더에 파일이 저장되는 것은 아닙니다. 파일로 확보한 다음 브라우저에서 실행해 확인해야 합니다.

핵심: Web Chat은 아이디어, 요구사항, 간단한 코드 작성에 유용합니다.

06. 웹 Work로 결과물 만들기

하나의 답변보다 파일·사이트 등 완성된 결과물 제작이 목적일 때 사용합니다.

  1. ChatGPT 웹에서 제공되는 Work를 선택합니다.
  2. 목표와 입력 자료, 필요한 결과물, 제외 조건을 설명합니다.
  3. 작업에 필요한 접근 권한을 확인하고 허용합니다.
  4. 완성된 파일·사이트를 열어 핵심 기능을 직접 시험합니다.
  5. 내려받기·공유·게시 중 목적에 맞는 방법을 선택합니다.

Work는 문서·표·보고서뿐 아니라 작은 사이트·프로그램 결과물을 만드는 작업에도 쓸 수 있습니다. 다만 생성 결과물의 형식과 저장·공유 버튼은 작업 유형에 따라 다릅니다.

예시 지시문

첨부한 가상 매출 데이터로 연령 분석 표를 만들고, 결과 Excel과 사용법 안내 파일을 생성해 주세요.
열 이름을 먼저 확인하고, 잘못된 값은 임의로 고치지 말고 확인이 필요한 항목에 표시해 주세요.
완료 후 결과 파일 목록과 검증 방법을 알려 주세요.

핵심: Work는 여러 단계의 파일 작업과 결과물 완성에 맞는 방식입니다.

07. 웹 Codex Cloud 이해하기

원격 개발 컴퓨터에서 소스코드와 테스트를 다루는 Coding Agent 작업입니다.

Codex Cloud(클라우드 코덱스)는 OpenAI가 관리하는 원격 개발 환경에서 프로젝트를 만들거나 수정·테스트합니다. 지원되는 웹 진입 경로와 Cloud 환경 설정을 통해 작업할 수 있습니다. 일반 ChatGPT 화면의 Chat/Work 전환과 별도의 개발 작업 흐름입니다.

  1. 지원되는 Codex Cloud 경로에서 ChatGPT 계정으로 로그인합니다.
  2. GitHub 저장소와 개발 환경 연결·접근 범위를 설정합니다.
  3. 프로젝트와 작업 환경을 선택하고 요구사항을 입력합니다.
  4. Codex가 수정한 파일 차이(Diff)와 테스트 결과를 검토합니다.
  5. 승인한 변경을 저장소의 Commit 또는 Pull Request로 관리합니다.

각 Cloud 작업은 별도 작업 공간에서 실행될 수 있습니다. 다음 새 작업이 이전 작업의 커밋되지 않은 변경을 자동으로 이어받는다고 가정하지 않습니다.

핵심: 웹 Codex는 일반적으로 원격 개발 환경의 저장소·파일을 작업하며 내 PC 임의 폴더를 자동으로 읽지 않습니다.

08. 데스크톱 앱 설치와 화면 읽기

새 ChatGPT 데스크톱 앱은 ChatGPT의 Chat·Work와 별도의 Codex 화면을 제공합니다.

  1. OpenAI 공식 데스크톱 안내에서 Windows 또는 macOS용 앱을 설치합니다.
  2. Plus 계정으로 로그인합니다.
  3. 메뉴에서 ChatGPT 또는 Codex를 선택합니다.
  4. ChatGPT 화면에서는 Chat과 Work를 전환합니다.
  5. 작업 중 생성된 파일 또는 프로젝트의 실제 저장 위치를 확인합니다.

새 앱과 기존 ChatGPT Classic이 동시에 설치될 수도 있습니다. 메뉴 이름은 앱 버전과 계정에 따라 바뀔 수 있으므로 현재 화면의 실제 명칭을 우선합니다. Chat·Work와 Codex의 작업 기록은 별도로 보일 수 있습니다.

핵심: ChatGPT 안에서 Chat·Work를 선택하고, 소프트웨어 개발은 Codex 화면에서 진행합니다.

09. 데스크톱 Chat 이용하기

웹에서 하던 요구사항 대화를 데스크톱에서 이어갈 때 유용합니다.

  1. 데스크톱 앱을 열고 ChatGPT → Chat으로 이동합니다.
  2. 웹에서 사용한 것과 같은 계정인지 확인합니다.
  3. 기존 대화 또는 새 대화를 열고 요구사항을 구체화합니다.
  4. 코드·설명·파일을 검토한 후 필요한 파일을 저장합니다.

같은 계정의 일반 Chat 대화는 지원되는 웹·데스크톱 환경에서 이어 볼 수 있습니다. 단, 대화가 동기화된다는 뜻과 코드 파일이 자동으로 내 PC 프로젝트 폴더에 저장된다는 뜻은 다릅니다.

핵심: 데스크톱 Chat은 대화의 연속성이 장점이며, 작업 파일의 위치는 별도 확인합니다.

10. 데스크톱 Work: Cloud와 Local

같은 Work라도 원격 작업과 내 PC 폴더 작업은 구별해야 합니다.

구분작업 방식결과 확인
Cloud WorkOpenAI 측 작업 환경에서 자료 분석·파일·사이트 제작제공되는 파일 및 결과물에서 확인·다운로드
Local Work권한을 부여한 로컬 폴더·도구에 접근해 작업실제 PC 폴더의 변경 파일 확인
  1. 데스크톱 앱에서 ChatGPT → Work를 선택합니다.
  2. Cloud 작업인지 Local 프로젝트·폴더 작업인지 확인합니다.
  3. Local이면 대상 폴더만 지정하고 필요한 권한을 허용합니다.
  4. 작업 완료 후 파일 목록과 변경 내용을 직접 확인합니다.

Local Work 접근 가능 여부는 계정·권한·제공 상태에 따라 다를 수 있습니다. 로컬에서 작업하더라도 지시문이나 필요한 일부 맥락은 Cloud로 전송·저장될 수 있습니다.

핵심: Work의 “내 PC 폴더 접근” 여부는 현재 작업 환경과 부여한 권한으로 판단합니다.

11. 데스크톱 Codex: Local 개발

프로젝트 폴더에서 실제 코드를 고치고 테스트하고 싶다면 Local Codex를 사용합니다.

  1. 데스크톱 앱에서 Codex를 선택합니다.
  2. Local 작업을 선택하고 실제 프로젝트 폴더를 지정합니다.
  3. 자연어로 만들 기능과 검증 기준을 설명합니다.
  4. Codex가 파일을 수정하고 테스트한 결과를 확인합니다.
  5. 변경 파일 목록·Diff·실행 결과를 검토합니다.
  6. 필요할 때 Git Commit으로 이력을 남기고 공개·Push는 별도 승인합니다.

Local Codex는 PC의 폴더·터미널 등 개발 도구를 다루면서 OpenAI의 Cloud LLM을 사용할 수 있습니다. 중요한 작업일수록 파일 변경 및 명령 실행 권한을 확인합니다.

예시 요청

이 프로젝트 폴더에 한글 타자 연습 웹앱을 만들어 주세요.
먼저 현재 폴더 상태를 확인하고 기획안을 보여 주세요.
제가 승인한 뒤 코드를 작성하고 실행 테스트를 해 주세요.
기존 파일이 있다면 변경 전에 목록을 보고하고, 완료 후 수정 파일과 테스트 결과를 정리해 주세요.

핵심: Local Codex는 내가 지정한 폴더의 프로그램을 계속 고쳐 쓰는 작업에 적합합니다.

12. 같은 과제를 여섯 환경에서 보기

같은 요구사항이라도 프로그램이 만들어지는 위치와 관리 방법은 다릅니다.

작업 위치주된 결과다음에 할 일
웹 Chat대화 속 코드·첨부 결과물파일 확보 후 실행·저장
웹 WorkCloud 제작 결과물다운로드·공유 및 검수
웹 Codex Cloud원격 프로젝트 변경 및 테스트Commit/PR 검토 후 저장소 반영
데스크톱 Chat대화 및 파일 결과물프로젝트 폴더 반영 여부 확인
데스크톱 Local Work로컬 폴더 작업 결과변경 파일 검수
데스크톱 Local Codex로컬 코드·테스트·Git 변경Diff·테스트 검토 및 Commit

예를 들어 같은 “한글 글쇠 20회 반복 입력” 기능을 요청했을 때, 모든 방식이 자연어를 받아들일 수 있습니다. 선택 기준은 개발자 여부가 아니라 파일 접근, 테스트, 수정과 이력 관리가 얼마나 필요한지입니다.

핵심: Chat → Work → Codex는 권장 학습 서열이 아니라 사용 가능한 작업 방식의 나열입니다.

13. 결과물 확보·저장·배포

AI가 파일을 만들었다는 사실과 그 파일을 내가 통제한다는 사실은 다릅니다.

단계해야 하는 일
생성(Create)요구사항으로 결과물을 만듭니다.
확보(Save/Export)내 PC 또는 관리 가능한 저장소에 원본을 보관합니다.
검증(Test)실제로 실행하고 기준에 맞는지 확인합니다.
배포(Deploy)승인 후 필요한 사용자에게 실행 환경을 제공합니다.

웹에서 받은 파일은 다운로드 위치와 실제 확장자를 확인합니다. Codex Cloud에서 저장소에 반영한 결과는 내 PC에서 Clone 또는 Pull로 가져올 수 있습니다. GitHub에 코드만 올렸다고 자동으로 모든 프로그램이 웹사이트로 배포되는 것은 아닙니다.

핵심: 대화 기록, 파일 원본, Git 저장소, 배포된 웹사이트는 서로 다른 저장·이용 대상입니다.

14. Git과 GitHub의 기본 사용법

프로젝트를 계속 수정한다면 원본과 변경 이력을 보관합니다.

Git(깃)은 변경 이력을 기록하는 버전 관리 도구이고, GitHub(깃허브)는 Git 저장소를 온라인에서 보관·협업하는 서비스입니다. Repository(리포지터리, 저장소)는 프로젝트 파일과 버전 이력이 있는 공간입니다.

용어뜻
Clone원격 저장소를 내 PC에 처음 복제
Commit변경을 하나의 기록으로 남김
Push로컬 기록을 원격 저장소에 올림
Pull원격 변경을 로컬에 가져와 반영
Branch기본 흐름과 분리된 작업 갈래
Fork다른 사람의 저장소를 내 계정으로 별도 복제
Pull Request(PR)Branch 변경을 병합해 달라고 제안·검토 요청
Merge검토된 변경을 실제로 합침

예: 팀 저장소를 Fork(필요할 때) → Branch에서 수정 → Commit·Push → PR 제출 → Merge. 내 저장소 안에서도 Fork 없이 Branch → PR → Merge를 할 수 있습니다.

핵심: PR은 병합 요청이고 Merge는 병합 실행입니다.

15. 이용량·비용·API 구분

Plus 구독과 외부 API 호출은 별도로 이해해야 합니다.

ChatGPT Plus는 정기 구독 서비스입니다. 공식 기본 안내 금액은 월 미화 20달러이며 세금·결제 경로에 따라 실제 청구액이 달라질 수 있습니다. 기능 및 사용량 한도는 변경될 수 있습니다.

API(Application Programming Interface, 응용 프로그램 연결 인터페이스)는 별도 프로그램에서 모델 기능을 호출하기 위한 연결 방식입니다. ChatGPT Plus 구독료에 OpenAI API 사용요금이 자동 포함되는 것은 아닙니다. 외부 서비스와 연결할 때는 로그인 방식과 별도 과금 여부를 확인합니다.

사용량 제한이 발생했을 때는 기능별 안내와 실제 계정 화면을 확인합니다. 특정 모델이 항상 선택 가능하다거나 한도가 영구히 고정된다고 가정하지 않습니다.

핵심: Plus 구독, Codex 제공 사용량, API 별도 청구는 각각의 실제 조건을 확인합니다.

16. 검수와 공개 안전

정확한 요구사항과 사람의 검증이 AI 개발의 품질을 결정합니다.

  1. 소스코드가 기대한 기능을 수행하는지 시험합니다.
  2. 실제 파일·폴더와 Git Repository Root를 확인합니다.
  3. README에 목적·실행·사용법이 있는지 확인합니다.
  4. 공개 대상 파일 목록을 살피고 관련 없는 자료를 제외합니다.
  5. API Key·Token·.env·Credential·개인정보·결제 정보·내부 대화 기록·로그가 없는지 점검합니다.
  6. 최종 승인 후에만 Push·배포·공개합니다.

민감한 정보를 실수로 포함했다면 단순히 파일에서 지우는 것으로 Git 이력 노출까지 해결되는 것은 아닐 수 있습니다. 원본과 변경 이력을 함께 점검합니다.

핵심: 파일·이력·배포 내용의 최종 책임은 Owner가 가집니다.

17. 집에서 혼자 해 보는 첫 실습

간단한 HTML 하나로 바이브코딩을 경험하고 필요한 만큼 발전시킵니다.

  1. ChatGPT Plus 계정으로 로그인합니다.
  2. Chat, Work, Codex 중 사용하려는 작업 방식과 결과 파일의 저장 장소를 선택합니다.
  3. “반복할 일·입력·처리 규칙·결과·검증 기준”을 네 줄로 적습니다.
  4. 먼저 계획을 보고받고 승인한 다음 MVP를 만들게 합니다.
  5. 실행·수정·검수 후 결과 파일을 내 PC 또는 GitHub에 안전하게 보관합니다.

따라 쓰는 기본 프롬프트

저는 코드를 직접 작성하지 않고 자연어로 프로그램을 만들려고 합니다.
목적: [어떤 반복 문제를 해결할지]
입력: [어떤 데이터를 받을지]
처리 규칙: [어떤 기준으로 처리할지]
결과: [화면/파일 등 어떤 결과를 만들지]
검증 기준: [어떻게 정확함을 확인할지]
이번 버전에서 제외할 것: [제외 범위]
먼저 이해한 내용을 요약하고, MVP 기획안과 확인이 필요한 질문을 알려 주세요.
제 승인 전에는 개발을 시작하지 마세요.

핵심: 작은 문제 하나부터 직접 만들고, 확인하고, 고쳐 보십시오.

18. 자주 묻는 질문과 공식 자료

실제 화면의 이름이나 제공 기능이 달라졌다면 현재 공식 안내를 확인합니다.

Codex는 개발자만 쓰나요?
아닙니다. 자연어로 시작할 수 있습니다. 프로그램이 복잡할수록 결과 검증과 관리가 중요합니다.

웹 Chat과 데스크톱 Chat은 이어지나요?
같은 계정의 일반 Chat 대화는 지원되는 환경에서 동기화됩니다.

데스크톱을 설치하면 LLM이 내 PC에서 도나요?
아닙니다. 기본적으로 Cloud 모델을 사용하며 로컬 파일·명령 작업과 구분합니다.

Cloud Codex가 내 PC 바탕화면을 곧바로 고칠 수 있나요?
일반적인 Cloud 작업은 원격 작업 공간을 사용합니다. 내 PC의 폴더를 고치려면 Local 작업을 선택합니다.

GitHub에 올리면 바로 공개 사이트인가요?
아닙니다. 소스 보관과 배포는 별개입니다.

Plus에 API 비용이 포함되나요?
아닙니다. API 사용요금은 별도로 관리합니다.
