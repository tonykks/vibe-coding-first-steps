Tony’s Library를 만든 하루(2026-10-27)의 인계 파일에서 고른 장면

Agent들은 서로 직접 대화하지 않습니다. 한 Agent가 파일을 남기면 Owner가 다음 Agent에게 “읽어 줘”라는 짧은 신호만 전하고, 다음 Agent가 그 파일을 읽고 이어서 일합니다. 아래는 가상의 예시가 아니라 실제 프로젝트 폴더의 handoffs/에 남은 파일입니다. 같은 날 약 60개의 파일이 오갔고, 그중 한 바퀴를 순서대로 골랐습니다.

파일 내용은 원문 그대로이며, 길어서 줄인 곳은 “…”로 표시했습니다. 공개 자료이므로 Owner를 부르는 호칭 한 가지만 “Owner”로 바꿨습니다.

## BLOCKING 1 — confirm 보존 Gate가 정상적인 본문 다듬기를 차단함

`ConfirmService.confirm_document()`는 매 confirm마다 현재 `draft/page.html`을 최초 `originals/.../source.html`과 직접 비교하고, 조금이라도 달라지면 `PRESERVATION_CHECK_FAILED`로 중단한다. 그러나 승인된 흐름은 import 직후 원문 보존을 확인한 뒤 1바퀴에서 본문을 Owner의 말로 다듬고, 2바퀴에서 장면별 요약·스크립트를 보강한 후 확정하는 것이다. 따라서 현재 Gate는 핵심 사용자 흐름과 충돌한다. 기존 테스트는 본문을 변경하지 않고 memo/script만 바꾸므로 이 회귀를 잡지 못한다.

### 필요한 수정·검증

- import 시점의 자동 변환 보존 검증과, 이후 Owner 편집의 허용·검토 기준을 분리한다.
- confirm은 import 기준선 자체의 무단 변경/미해결 보존 실패는 막되, 승인된 1바퀴 본문 편집은 확정할 수 있어야 한다.
- 실제로 `page.html` 본문을 다듬은 뒤 confirm이 성공하는 회귀 테스트와, 원본/기준선 변조 또는 미해결 import 실패는 차단되는 테스트를 함께 추가한다.
