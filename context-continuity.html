01

무엇이 넘어가고 무엇이 막히는가

대화 내용 전체가 공유되는 것이 아닙니다. 공유되는 것은 대화에서 골라낸 핵심 사실, 즉 메모리입니다.

구분무엇이 넘어가나다른 프로젝트에서
메모리대화에서 골라낸 오래 쓸 사실 몇 줄 (예: 강연 제목, 날짜)보입니다 (스위치가 켜져 있을 때)
대화 원문주고받은 글 전체보이지 않습니다

지난 대화 검색의 칸막이

  • 프로젝트 안에서는 그 프로젝트의 대화만 찾아봅니다. 같은 프로젝트에서 “지난번 그 얘기”라고 하면 찾아서 읽으므로 맥락이 이어진다고 느끼게 됩니다.
  • 프로젝트 밖에서는 프로젝트 밖 대화만 찾아봅니다.
  • 검색은 필요할 때 찾아보는 방식입니다. 모든 지난 대화를 자동으로 읽고 시작하지는 않습니다.
직접 확인

「Claude 이해하기」 프로젝트에서 다른 프로젝트의 대화 제목 “강연 보충자료 작성 개요”로 검색했더니 찾지 못했습니다. 사이드바에는 그 대화가 분명히 있었습니다.

02

프로젝트 메모리 스위치 확인하기

프로젝트마다 계정 메모리와 연결할지 따로 둘지 정하는 스위치가 있습니다.

왼쪽 메뉴›프로젝트›프로젝트 열기›메모리 보기
스위치결과이럴 때
켜짐 (기본)계정 메모리가 이 프로젝트에 들어오고, 이 프로젝트의 메모리도 프로젝트 밖 대화와 공유됩니다.대부분의 작업
꺼짐양쪽 모두 막힙니다. 이 프로젝트의 기억은 밖으로 나가지 않고, 밖의 기억도 들어오지 않습니다.건강 기록, 고객 자료처럼 섞이면 안 되는 작업
03

계정 메모리에 핵심 올리기

프로젝트를 넘나들어야 할 사실은 프로젝트 밖 일반 대화에서 “메모리를 업데이트해 줘”라고 분명히 말합니다. 가장 간단하고 확실한 통로입니다.

  1. 왼쪽 맨 위 새 생성을 누릅니다.
  2. 입력칸 아래 프로젝트 선택을 비워 둡니다. 여기서 프로젝트를 고르면 그 프로젝트 안의 대화가 됩니다.
  3. 바뀐 사실과 지울 사실을 함께 적어 보냅니다.
요청 문장 틀
메모리를 업데이트해 줘. [무엇]은 [새 내용]이야. 예전 [예전 내용]은 지워 줘.
직접 확인

업데이트 직후 다른 프로젝트의 대화에서 강연 제목을 확인했더니 새 제목이 보였습니다. 프로젝트 밖에서 올린 사실이 프로젝트 안으로 넘어간 것입니다.

메모리 관리 기준

  • 꼭 남길 것은 분명히 말합니다. 무엇을 기억할지는 Claude가 고르므로, 사소한 이야기까지 다 저장되지는 않습니다.
  • 많을수록 좋은 것은 아닙니다. 메모리는 주제별 파일로 나뉘어 저장되고 파일마다 크기 제한이 있습니다. 오래되거나 틀린 기억은 틀린 답의 원인이 됩니다.
  • 한 달에 한 번 점검합니다. 설정 › 메모리 › 내보내기로 받아 훑어보고, 바뀐 것은 “고쳐 줘”, “지워 줘”라고 말합니다.
04

바깥 기록장으로 작업 상태 잇기

메모리는 사실 몇 줄을 넘기기에 좋지만, 작업이 지금 어디까지 왔는지는 한 페이지로 정리해 두는 편이 정확합니다. Notion 페이지 하나를 그 작업의 현재 상태판으로 쓰고, 새 대화마다 먼저 읽게 합니다.

전제: Claude에 Notion 커넥터를 연결해 두었습니다. 기록장 위치는 어디든 상관없고, 연결할 때 허용한 범위 안에만 있으면 됩니다.

1. 현재 상태 페이지 만들기

Notion에 빈 페이지를 만들고 주소를 Claude에게 알려 준 뒤, 지금까지 정한 내용을 요약해 기록해 달라고 합니다.

2. 프로젝트 지침 맨 위에 주소 적기

작업 시작 규칙 (주소만 바꿔 쓰세요)
[작업 시작 규칙]
이 프로젝트에서 새 대화를 시작하면, 먼저 Notion의 「(페이지 이름)」 페이지를 읽고 현재 상황을 파악한 뒤 답해 주세요.
(페이지 주소)
작업이 한 단락 끝나거나 결정이 바뀌면, 그 페이지의 해당 항목을 고칠지 저에게 먼저 묻고, 제가 승인하면 반영해 주세요. 페이지는 일지가 아니라 최신 요약판으로 유지해 주세요.

3. 새 대화에서 확인하기

기록장 운영 기준

  • 읽으라고, 적으라고 말해야 합니다. 읽기는 지침이 대신 말해 주고, 기록은 작업이 한 단락 끝날 때 “상태 페이지에 반영해 줘”라고 합니다.
  • 짧게 유지합니다. 길어지면 읽는 데 사용량이 들고 핵심이 묻힙니다. 현재 위치, 결정된 것, 다음 할 일만 둡니다.
  • 바꾸기 전에 묻게 합니다. 기록장은 판단의 기준이므로, 고치는 결정은 사람이 승인합니다.
기록장 위치잘 맞는 일특징
Notion 페이지강연 준비, 기획처럼 코드 없는 일스마트폰에서도 읽고 고치기 쉬움. 허용 범위 확인 필요
GitHub 파일코딩 프로젝트변경 이력이 정확히 남고 IDE 안의 에이전트가 바로 읽음. 공개 저장소는 누구나 볼 수 있음
이 방식은 대화창이 기억하게 하는 대신, 작업 기록이 기억하게 하는 방법입니다. 같은 기록장을 다른 AI나 IDE의 코딩 에이전트도 읽을 수 있습니다.
05

사용량 화면 읽는 법

유료 플랜은 무제한이 아니라 두 겹의 한도 안에서 씁니다. 화면을 읽을 줄 알면 긴 작업을 언제 맡길지 정할 수 있습니다.

설정›사용량

한도가 작동하는 방식

  • 세션 한도를 다 쓰면 초기화 시각까지 기다렸다가 다시 씁니다. 주간 한도가 남아 있는 동안은 추가 비용이 없습니다.
  • 주간 한도까지 다 쓰면 다음 초기화까지 기다리거나, 사용량 크레딧을 사서 계속하거나, 플랜을 올립니다.
  • 웹, 데스크톱, 모바일, Claude Code의 사용량이 모두 같은 한도에 합산됩니다. 창을 여러 개, 기기를 여러 대 써도 문제는 없지만 한도는 하나입니다.
  • Claude Code에 맡긴 작업은 한도에 닿으면 그 자리에서 멈춥니다. 작업을 작게 나누고 단계마다 저장해 두면 초기화 뒤 이어서 할 수 있습니다.
구분하는 일예
채팅대화로 묻고 답을 받음개념 설명, 문장 다듬기, 검색해서 답하기
CoworkClaude가 작업 공간에서 여러 단계 작업을 직접 수행파일 읽고 쓰기, 이미지 자르기, 웹페이지 만들어 게시하기

사용량을 빨리 쓰는 것

  • 파일 만들기, 코드 실행, 웹 검색, 커넥터 사용 같은 도구 작업
  • 아주 긴 대화와 큰 첨부 파일 (주제가 바뀌면 새 대화를 여는 편이 낫습니다)
  • 더 높은 성능의 모델과 깊은 사고 설정
커넥터를 여러 개 연결해도 Claude 쪽 추가 요금은 없습니다. 쓸 때 사용량이 들 뿐입니다. PowerPoint나 Excel 파일도 Office 프로그램을 빌려 쓰는 것이 아니라 Claude가 작업 공간에서 직접 파일을 만들기 때문에 Office 라이선스가 필요 없습니다.
06

상황별로 고르기

세 가지 통로는 서로 대신하는 관계가 아니라 쓰임이 다릅니다.

이럴 때이렇게
같은 일을 여러 날 이어서 한다같은 프로젝트 안에서 대화한다
바뀐 사실을 모든 곳에 알려야 한다프로젝트 밖 대화에서 “메모리를 업데이트해 줘”
작업의 진행 상태를 정확히 이어야 한다바깥 기록장 + 프로젝트 지침에 주소
섞이면 안 되는 자료를 다룬다프로젝트의 계정 메모리 사용을 끈다
긴 작업을 맡기려 한다사용량 화면에서 남은 한도를 먼저 본다
AI가 지난 일을 알아서 기억해 주기를 기대하기보다, 무엇을 어디에 남길지 사람이 정해 두면 대화가 바뀌어도 일이 끊기지 않습니다.
