git과 GitHub, 사진첩으로 이해하기

바이브코딩을 하다 보면 AI가 자꾸 "commit 할까요?", "GitHub에 push 할까요?"라고 묻습니다. 이 글은 그 말들이 무엇이고 왜 필요한지, 사진첩 하나로 풀어 봅니다.

0 · 왜 필요할까

보고서_최종, 보고서_진짜최종

보고서를 쓰다 보면 이런 파일이 쌓입니다.

  • 보고서.hwp
  • 보고서_최종.hwp
  • 보고서_진짜최종.hwp
  • 보고서_진짜진짜최종.hwp

고치기 전 것을 지우기 불안해서입니다. 어제 판이 더 나았을지도 모르고, 무엇을 바꿨는지 나중에 확인하고 싶기도 합니다. 사람은 이렇게 파일 이름을 바꿔 가며 손으로 버전 관리를 합니다.

프로그램은 더합니다. AI가 한 번에 파일 여러 개를 고치고, 하루에도 수십 번 고칩니다. 이름을 바꿔 가며 보관하는 것으로는 따라갈 수 없습니다. 그래서 바뀐 내용을 자동으로 기록하고, 필요하면 그때로 되돌려 주는 도구를 씁니다. 그것이 git이고, 한 번 기록하는 일이 commit입니다.

git은 "_최종, _진짜최종"을 대신해 주는 버전 관리 도구입니다.

1 · 한 장의 비유

사진 한 장, 사진첩 하나, 인터넷 사진첩

폴더 하나를 사진첩으로 관리한다고 생각해 보십시오. 고칠 때마다 그 순간의 폴더 전체를 사진으로 찍어 둡니다. 사진 밑에는 무엇을 바꿨는지 한 줄을 적습니다. 이 사진 한 장이 commit이고, 사진첩이 git, 사진첩을 인터넷에 둔 사본이 GitHub입니다.

이름비유하는 일
commit사진 한 장 + 설명 한 줄그 순간 폴더 전체를 기록. b5f3bb0 같은 번호가 붙습니다
git내 PC의 사진첩사진을 순서대로 보관하고, 원하는 번호의 그때 모습으로 되돌립니다
GitHub인터넷에 둔 사진첩 사본다른 PC·다른 사람과 같은 사진첩을 함께 봅니다

사진첩은 저절로 생기지 않습니다. 폴더에서 git init을 한 번 해야 생깁니다. 새 프로젝트를 시작할 때 AI에게 이렇게 한 줄을 덧붙이면 됩니다.

새 프로젝트를 시작할 때 덧붙일 한 줄
이 폴더를 git으로 관리하고, 큰 수정을 마칠 때마다 commit 해 줘.

commit은 사진, git은 내 PC의 사진첩, GitHub은 인터넷에 둔 사진첩입니다.

2 · commit

AI가 왜 자꾸 commit 하자고 할까

바이브코딩에서는 AI가 한 번에 여러 파일을 고칩니다. 잘 되던 기능이 다음 수정에서 깨지는 일도 흔합니다. 이때 사진이 있으면 "어제 오후 사진으로 돌아가 줘" 한마디로 되돌릴 수 있습니다. 사진이 없으면 무엇이 바뀌었는지부터 찾아야 합니다.

  • 되돌릴 자리: 고장 나면 마지막으로 잘 되던 사진으로 돌아갑니다.
  • 바뀐 곳 보기: 앞 사진과 견주면 몇 줄이 어떻게 바뀌었는지 보입니다(git diff).
  • 기록: 사진 설명을 이어 읽으면 이 프로그램이 자라 온 길이 됩니다.

그래서 commit은 "잘 되는 것을 확인한 뒤"에 하는 것이 좋습니다. 고치고, 시험해 보고, 괜찮으면 찍습니다.

commit은 되돌아올 수 있는 자리를 만드는 일입니다.

3 · push와 pull

push와 pull: 두 사진첩 맞추기

사진첩은 두 곳에 있습니다. 내 PC의 사진첩과 GitHub의 사진첩. GitHub에서 저장소(repository)를 만들면 빈 사진첩이 하나 생기고, 그다음부터는 새 사진만 오갑니다.

말방향언제 쓰나
push내 PC → GitHub내가 찍은 새 사진을 올릴 때
pullGitHub → 내 PC다른 PC나 다른 사람이 올린 사진을 내려받을 때
cloneGitHub → 새 PC사진첩을 처음 통째로 복사해 올 때

노트북과 데스크톱을 오가며 일한다면, 시작할 때 pull, 마칠 때 push가 기본 습관입니다. commit만 하고 push하지 않으면 사진은 내 PC에만 있습니다.

push는 올리기, pull은 내려받기. 두 사진첩을 같게 맞추는 일입니다.

4 · 배포

배포: 내 PC 밖으로 내보내기

내 PC에서 만든 웹페이지는 내 PC에서만 열립니다. 주소창에 file:///C:/...로 시작하는 주소는 다른 사람에게 보내도 열리지 않습니다. 다른 사람이 인터넷 주소로 열 수 있게 하는 일이 배포입니다.

GitHub에는 GitHub Pages라는 무료 배포 기능이 있습니다. 저장소에 올린 html 파일을 그대로 웹사이트로 보여 줍니다. 이 강연 사이트도 이렇게 배포했습니다.

처음 한 번만 GitHub에서 켜 두면 됩니다. 누르는 곳은 이렇습니다.

  1. github.com에서 내 저장소를 엽니다.
  2. 위쪽 메뉴 맨 오른쪽 Settings(톱니바퀴)를 누릅니다.
  3. 왼쪽 메뉴에서 Pages를 누릅니다.
  4. Source가 "Deploy from a branch"인지 봅니다.
  5. 그 아래 Branch 칸의 None을 main으로 바꾸고 Save를 누릅니다.
  6. 1~2분 뒤 같은 화면 위쪽에 https://아이디.github.io/저장소이름/ 주소가 나타납니다.

그다음부터는 내 PC에서 고치고 commit, push만 하면 1~2분 뒤 사이트가 새것으로 바뀝니다.

그래서 GitHub이 중요합니다. 사진첩 보관, 다른 PC와 공유, 웹사이트 공개가 한곳에서 무료로 됩니다. 공개 저장소라면 비용이 없습니다.

배포는 내 PC 안의 결과를 인터넷 주소로 내보내는 일이고, GitHub Pages는 그 가장 쉬운 길입니다.

5 · 다른 배포 사이트

GitHub Pages가 못 하는 일은 다른 곳에서

GitHub Pages는 정적 페이지만 보여 줍니다. 정적 페이지란 누가 열어도 같은 파일(html·css·js)을 그대로 내주는 페이지입니다. 반대로 동적인 일, 곧 서버에서 프로그램이 돌아야 하는 일은 못 합니다.

GitHub Pages로 되는 것GitHub Pages로 안 되는 것
강의 자료·설명 페이지·포트폴리오로그인, 회원 정보 저장
브라우저 안에서만 도는 계산기·타이머·게임데이터베이스에 쓰고 읽기
미리 만들어 둔 표와 그래프비밀 열쇠(API Key)를 숨겨 두고 AI 부르기

이런 일은 Vercel, Netlify, Render, Firebase 같은 배포 사이트가 맡습니다. 이들도 출발점은 GitHub입니다. 저장소를 한 번 연결해 두면, 내가 push할 때마다 그 사이트가 GitHub에서 새 사진을 가져가(pull) 다시 만들고 배포합니다.

  1. 내 PC에서 commit → GitHub에 push
  2. 배포 사이트가 GitHub에서 새 코드를 가져감
  3. 그 사이트의 서버에서 실행·배포

어디에 배포하든 코드의 집은 GitHub입니다. 정적이면 GitHub Pages, 서버가 필요하면 다른 사이트가 GitHub에서 가져갑니다.

6 · React와 Vite

React·Vite로 만든 화면도 GitHub Pages에 올릴 수 있습니다

"React·Vite로 만든 것은 GitHub Pages로는 안 되고 Vercel 같은 곳에 올려야 한다"는 설명을 자주 듣습니다. 반만 맞습니다. 그대로 올리면 안 되는 것은 맞지만, build를 거치면 됩니다.

React·Vite 코드

  • 밀키트: 재료와 조리법
  • 브라우저가 바로 먹지 못함

build한 결과(dist 폴더)

  • 다 차린 요리: 평범한 html·css·js
  • 정적 페이지라 GitHub Pages에 올릴 수 있음

조리(build)를 어디서 하느냐에 따라 길이 두 가지입니다.

GitHub이 조리하는 길내 PC에서 조리해 올리는 길
하는 일push하면 GitHub Actions가 build하고 배포내 PC에서 build한 결과를 gh-pages라는 갈래(branch)에 올림
GitHub에서 바꿀 곳Settings → Pages → Source를 GitHub Actions로Settings → Pages → Branch를 gh-pages로 → Save
고친 뒤push만 하면 저절로고칠 때마다 배포 명령을 다시 실행
안내한 곳Vite 공식 안내React + Vite GitHub Pages Guide

바이브코딩이라면 첫째 길이 편합니다. 내가 바꿀 곳은 Settings → Pages → Source를 GitHub Actions로 한 군데뿐이고, 나머지 준비는 AI에게 시키면 됩니다.

AI에게 할 말
이 React·Vite 앱을 build해서 GitHub Pages에 배포해 줘.
GitHub Actions로 하고, 내가 GitHub에서 바꿀 곳도 알려 줘.

React·Vite도 build하면 정적 페이지입니다. GitHub Pages에 올릴 수 있습니다.

7 · Actions

Actions: 정해진 때 저절로 돌아가는 일꾼

GitHub Actions는 GitHub 안의 컴퓨터를 잠깐 빌려 정해진 일을 시키는 기능입니다. 6절에서 GitHub이 대신 build해 준 것도 Actions였습니다. 내 PC가 꺼져 있어도 돌아갑니다.

Actions가 돌리는 것은 html 파일이 아니라 프로그램입니다. 예를 들어 매일 아침 자료를 모아 현황 페이지를 새로 만드는 프로그램을 돌리면, 그 결과가 GitHub Pages에 올라가 사이트가 저절로 바뀝니다. 자동화와 배포가 여기서 만납니다.

언제 돌릴까예
push할 때마다build해서 배포, 자동 검사
정해진 시각마다매일 아침 6시에 자료를 모아 현황 페이지 갱신
내가 버튼을 누를 때필요할 때만 한 번 실행

쓰는 순서

  1. 할 일을 정합니다. 무엇을, 언제 돌릴지.
  2. AI에게 말합니다. "Actions로 매일 아침 6시에 ○○가 돌게 해 줘."
  3. AI가 설정 파일을 만들어 push합니다. 파일은 저장소의 .github/workflows/ 폴더에 들어갑니다.
  4. 저장소 위쪽 메뉴 Actions를 누르면 실행 기록이 보입니다. 노란 동그라미는 진행 중, 초록 체크는 완료, 빨간 X는 실패입니다.
  5. 빨간 X가 나오면 눌러서 오류 문장을 복사해 AI에게 붙여 넣습니다.
  • 시각은 세계 표준시 기준이라 AI가 한국 시각으로 바꿔 적습니다. "한국 시각 6시"라고 말하면 됩니다.
  • 정해진 시각보다 몇 분 늦게 돌 수 있습니다.
  • 공개 저장소는 무료, 비공개 저장소는 한 달 2,000분까지 무료입니다.

Actions는 GitHub 안의 일꾼입니다. 무엇을 언제 할지만 정해 AI에게 말하면 됩니다.

8 · 덤

git이라는 이름의 장난

2005년, 리눅스 개발자들은 BitKeeper라는 유료 버전 관리 프로그램을 무료로 빌려 쓰고 있었습니다. 그런데 한 개발자가 BitKeeper의 작동 방식을 뜯어보다가 회사와 다툼이 생겼고, 회사는 무료 사용을 거둬 갔습니다. 리눅스를 만든 리누스 토르발스는 "그럼 내가 만든다" 하고 약 열흘 만에 git의 뼈대를 내놓았습니다.

git은 영국 속어로 "멍청하고 고집 센 녀석"이라는 뜻입니다. 리누스는 "나는 자기중심적이라 프로젝트마다 내 이름을 붙인다. 처음엔 Linux, 이번엔 git"이라고 농담했습니다. 자기를 고집 센 녀석이라 부른 셈입니다. 첫 설명서에도 장난이 있습니다. 기분 좋을 때 읽으면 Global Information Tracker(세계 정보 추적기), 고장 났을 때 읽으면 욕설 섞인 말의 머리글자라고 적어 두었습니다.

사실 Linux라는 이름도 리누스가 붙인 것이 아닙니다. 그는 'Freax'라는 이름을 원했는데, 파일을 올려 준 서버 관리자가 폴더 이름을 'linux'(Linus + Unix)로 붙였고 그 이름이 굳었습니다.

3년 뒤인 2008년, git 사진첩을 인터넷에 맡기고 여럿이 함께 일하는 사이트가 문을 열었습니다. 이름은 GitHub, git이 모이는 중심(hub)이라는 뜻입니다. 2018년 Microsoft가 GitHub을 사들였고, 지금은 Copilot 같은 AI 기능이 더해졌습니다. 같은 회사의 무료 코딩 프로그램 VS Code에도 Copilot이 들어 있어, GitHub과 연결해 Copilot AI를 쓸 수 있습니다.

9 · 낱말

낱말 한눈에

낱말한 줄 풀이
repository(저장소)사진첩 하나. 보통 프로젝트 폴더 하나와 같습니다
commit그 순간 폴더 전체를 찍은 사진 + 설명 한 줄
branch사진첩 안의 갈래. 본 줄기(main)를 건드리지 않고 따로 고쳐 보는 자리
merge갈래에서 고친 것을 본 줄기에 합치기
push / pull / clone올리기 / 내려받기 / 처음 통째로 복사해 오기
build사람이 쓰기 편한 코드를 브라우저가 읽는 파일로 바꾸기
배포(deploy)결과를 인터넷 주소로 내보내기
정적 / 동적같은 파일을 그대로 내줌 / 서버에서 프로그램이 돌아 그때그때 만듦
GitHub Pages저장소의 정적 페이지를 무료 웹사이트로 보여 주는 기능
GitHub Actionspush·시각·버튼에 맞춰 GitHub 안의 컴퓨터가 정해진 일을 하는 기능
Pull Request"이렇게 고치자"는 제안. 검토한 뒤 합칩니다

고치고, 시험하고, 찍고(commit), 올리면(push), 세상에 보입니다(배포).

10 · 바이브코딩이라면

이렇게 말하면 됩니다

명령어를 외울 필요는 없습니다. 무슨 일인지만 알면 채팅창에 이렇게 시킬 수 있습니다.

채팅창에 할 말
commit하고 GitHub에 push해 줘.
GitHub Pages로 배포해 줘.
이 React·Vite 앱을 build해서 GitHub Pages에 배포해 줘.
Actions로 매일 아침 6시에 ○○가 돌게 해 줘.
어제 잘 되던 commit으로 되돌려 줘.

무슨 일인지만 알면 다 시킬 수 있습니다. 그것이 바이브코딩입니다.
