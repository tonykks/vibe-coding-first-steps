Vibe Agent 설정 가이드

ChatGPT와 Claude가 나를 같은 기준으로 이해하도록 설정하고, 대화로 내 생각을 요구사항으로 바꾸는 방법을 정리했습니다. 강연이 끝난 뒤 내 계정을 설정할 때 순서대로 따라 하시면 됩니다.

AI가 나를 알아서 이해하는 것이 아닙니다. 내가 나를 정리해서 알려주고, 그 기준을 여러 AI에 똑같이 맞출 때 비로소 여러 명의 Vibe Agent와 함께 생각을 다듬을 수 있습니다.

메뉴 이름과 위치는 계정, 요금제, 앱 버전에 따라 다를 수 있습니다. 본인 화면에 보이는 이름을 기준으로 따라 하세요.

01

Vibe Agent란

Vibe Agent는 내 생각을 듣고 질문과 비교로 요구사항을 함께 정리하는 대화 상대입니다.

Vibe Agent (바이브 에이전트) : 내가 하고 싶은 일을 듣고, 질문과 비교를 통해 목적·범위·완료 기준을 함께 정리하는 대화 상대. 강연에서 쓰는 역할 이름이며, 별도 제품이나 켜야 하는 기능은 아닙니다.

Agent(대리인, 代理人)는 라틴어 agere(행하다)에서 왔습니다. 나 대신 일을 맡아 처리하는 사람이라는 뜻으로, 부동산 중개인을 real estate agent라고 부르는 것과 같습니다.

  • 이 강연에서는 생각을 요구사항으로 정리하는 역할을 Vibe Agent, 코드를 구현하는 역할을 Coding Agent라고 구분합니다. 하나의 AI가 두 역할을 모두 수행할 수도 있습니다.
  • Vibe Agent와 나눈 대화의 결과가 Coding Agent에게 넘길 요구사항이 됩니다.
  • ChatGPT와 Claude를 함께 쓰면 같은 질문에 서로 다른 관점을 얻습니다. 비교가 공정하려면 두 AI가 나에 대해 같은 것을 알고, 같은 방식으로 답하도록 맞춰야 합니다.

03

처음 설정하는 순서

꺼내고, 대조하고, 확정한 뒤에 나눕니다. 나누기부터 하면 다시 고치게 됩니다.

  1. 꺼내기

    AI 설정에서 확인할 수 있는 메모리와 기존 지침을 살펴보고, "나에 대해 기억하는 내용을 정리해 주세요"라고 요청합니다. 대화로 확인한 결과가 전체 기억을 빠짐없이 보여주는 것은 아닙니다.

  2. 대조하기

    꺼낸 기억을 내 실제 기록(이력서, 노트, 일정표)과 비교해 중복·충돌·오래된 내용을 찾습니다.

    • 바뀐 회사·기관 이름이 예전 이름과 섞여 있음
    • 입학·졸업·근무 종료 시기가 실제와 다름
    • 그만 쓰는 도구가 아직 "사용 중"으로 남아 있음
    • 예전 지침("항상 자세히")과 최근 선호("짧게 한 단계씩")가 충돌
  3. 확정하기

    항목별로 직접 확인해 하나의 기준본을 만듭니다. AI가 정리해 주어도 확정은 내가 합니다.

  4. 나누기

    기준본을 02장의 표대로 나눕니다. 답변 방식은 지침, 나에 대한 사실과 진행 중인 일은 메모리, 특정 작업의 규칙은 프로젝트로 보냅니다.

  5. 맞추기

    같은 지침과 같은 기준본을 다른 AI에도 넣습니다.

  6. 시험하기

    짧은 질문 몇 개로 기대한 방식으로 답하는지 확인합니다(11장).

04

나를 소개하기

경력은 짧게, 지금 하는 일과 목표는 구체적으로 적습니다.

  • ChatGPT: 설정 → 개인 맞춤 설정 → More about you. 별명·직업 칸이 따로 있으면 나누어 적습니다.
  • Claude: 설정의 개인 지침 칸 앞부분에 소개 문장을 적고, "어떻게 불러드릴까요" 칸에 호칭을 맞춥니다.
  • 구독을 중단한 도구, 바뀐 개발환경, 끝난 계획은 현재 상태로 고칩니다. 한국어로 적어도 됩니다.
소개 문장 틀
저는 [직업·역할]입니다. [대상]에게 [하는 일]을 하고 있습니다.
AI와 대화하며 [만들고 싶은 것]을 직접 만들고, 그 과정을 [활용 목적]으로 정리하고 싶습니다.
현재 사용하는 도구는 [도구]이고, 당장의 목표는 [목표]입니다.
05

답변 방식 지침 쓰기

지침은 규칙 목록보다 "나는 이럴 때 이런 방식이 도움이 된다"는 1인칭 문장으로 씁니다.

  • 이유까지 적습니다. 이유를 알면 AI가 처음 보는 상황에도 응용합니다.
  • 적용 상황을 붙입니다. 조건 없이 넓게 쓴 지침은 서로 충돌합니다. 아래 표처럼 고칩니다.
  • 꼭 지킬 규칙은 언제 적용할지 조건과 함께 명확히 적습니다. 배경 정보("나는 ○○를 공부한다")는 관련 있는 질문에서만 반영되는 경향이 있습니다.
  • 모든 주제에 공통인 규칙만 넣습니다. 특정 프로젝트의 파일 경로나 기능은 프로젝트 지침으로 보냅니다.
  • 글자 수 제한이 보이면 실제 답변을 바꾸는 규칙부터 남기고, 중복 설명은 줄입니다.

조건을 붙이면 지침끼리 덜 부딪힙니다

넓게 쓴 지침적용 상황을 분명히 한 지침
모든 설명을 자세한 고정 순서로새 개념을 배울 때는 자세히, 실무와 복습은 간결하게

영어가 있으면 영어로 답변영어로 말을 걸면 영어로, 검토용 영어 자료는 한국어로 설명

답변 방식 지침 예시
정중한 한국어로 답해 주세요. 새로운 개념은 쉬운 정의와 큰 틀부터 설명하고, 주요 English 용어는 원어를 함께 적어 주세요. 처음부터 엄밀한 설명보다 큰 틀을 먼저 잡아야 제가 오래 기억합니다.
PC 설정·설치처럼 직접 따라 하는 작업은 버튼과 메뉴 경로 중심으로 한 번에 한 단계씩 안내해 주세요. 복습과 단순 확인은 짧게 답해 주세요.
요청이 불분명하면 먼저 확인하고, 요청한 범위를 넘어 작업을 시작하지 마세요. 최신 정보는 검색해 출처를 붙이고, 확실하지 않은 내용은 구별해 주세요.
먼저 쓸 수 있는 작은 버전을 만들어 확인한 뒤 개선해 주세요. 외부 전송·공개·배포 전에는 항상 최종 결과물과 민감정보 포함 여부를 보여 주고 제 승인을 받아 주세요.

말투 메뉴는 선택 사항입니다

ChatGPT의 "기본 스타일 및 톤"과 Claude 대화창의 "스타일" 메뉴는 말투와 길이를 조절합니다. 말투를 바꿔도 AI의 능력은 달라지지 않습니다. 지금 답변이 적절하면 그대로 두고, 길이와 설명 순서는 지침에서 구체적으로 정합니다.

06

메모리 점검하기

메모리는 저장된 내용이 지금도 사실인지 정기적으로 확인해야 합니다.

Memory (기억, 記憶) : 지난 대화의 유용한 맥락을 다음 대화로 이어 주는 기능. 매번 새로 쓰는 일기가 아니라 고쳐 가며 쓰는 수첩에 가깝습니다.
  • ChatGPT: 설정 → 개인 맞춤 설정 → 메모리 요약에서 현재 내용을 확인하고, 관리 화면에서 변경을 요청할 수 있습니다. 메모리 요약과 대화에서 확인한 내용은 모든 과거 대화·기억의 완전한 목록이 아닙니다.
  • Claude: 설정의 메모리 항목에서 보고 편집합니다. 예전 대화 검색·참조, 대화에서 메모리 생성, 민감한 주제 포함 여부를 각각 켜고 끌 수 있습니다.
  • 도구 변경, 프로젝트 종료, 계획 완료처럼 상태가 바뀌면 바로 고칩니다.
메모리 수정 요청 틀
메모리에서 다음 내용만 수정해 주세요.
1. [프로젝트 이름]은 개발 중이 아니라 [보관 중 / 완료]입니다.
2. [도구·장비]는 [새 상태]로 바뀌었습니다.
3. 한 번에 한 단계씩 안내하는 방식은 직접 따라 하는 작업에만 적용해 주세요.
나머지 내용은 그대로 유지해 주세요.
요청과 반영은 다릅니다

수정을 요청한 뒤에는 바뀐 메모리를 다시 읽어 확인합니다. 엉뚱한 항목에 중복으로 들어갔다면 삭제할 위치와 유지할 위치를 함께 지정합니다. 중요한 작업 기준은 메모리에만 두지 말고 프로젝트 지침과 기준 문서에도 적어 둡니다.

다른 AI의 기억 옮기기

  • Claude로 가져오기: 메모리 가져오기 기능에서 Claude가 주는 추출 프롬프트를 기존 AI에 넣고, 나온 결과를 붙여넣습니다. 기존 메모리를 덮어쓰지 않고 더해집니다.
  • ChatGPT로 옮기기: 확정한 기준본에서 핵심 사실을 골라 대화에 전달하고 메모리 반영을 요청합니다. 요청 후 실제 요약을 재확인하고, 누락·중복 여부를 점검합니다.
  • Claude에서 내보내기: 메모리를 Markdown 파일 묶음(.zip)으로 받아 백업할 수 있습니다. 실습 계정에서 받은 파일은 아래처럼 정리되어 있었습니다.
profile.md나는 누구인가: 이름, 역할, 지역, 언어
areas/진행 중인 일: 프로젝트별 상태와 결정
topics/나에 대한 사실과 습관: 경력, 개발 환경, 일하는 방식
projects/특정 프로젝트 안에서 생긴 기억

이 예시처럼 내보낸 기억을 주제별 파일로 살펴볼 수 있습니다. 강연 4부의 Harness가 Agent 사이의 문맥을 파일로 이어 주는 것과 같은 원리입니다. 이 파일을 다른 AI에 줄 때는 건강·투자처럼 민감한 파일을 빼고, "바로 저장하지 말고 수정안만 만들어 달라"고 요청합니다. 확정은 내가 합니다.

07

프로젝트 지침 정하기

계속 이어지는 작업은 프로젝트로 묶어, 새 대화를 열어도 같은 기준에서 시작하게 합니다.

Project (프로젝트) : 라틴어 pro(앞으로)와 jacere(던지다)에서 온 말로, 앞으로 내다 던진 계획이라는 뜻. 여기서는 관련 대화·파일·지침을 한곳에 모아 작업의 맥락을 유지하는 공간입니다.

1. 기존 지침부터 확인합니다

지침이 이미 있으면 처음부터 새로 쓰지 말고 바뀐 부분만 고칩니다. 한 프로젝트로 먼저 시험해 본 뒤 다른 프로젝트에 적용합니다.

기존 지침 점검 요청
이 프로젝트의 기존 지침과 제가 첨부한 최신 기준 문서 [파일 이름]을 비교해 주세요.
유지할 내용, 오래된 내용, 빠진 내용을 먼저 짧게 정리해 주세요.
아직 지침을 수정하거나 구현·배포하지 말고, 확인되지 않은 내용은 질문해 주세요.

2. 지침에 넣을 기본 항목

프로젝트 지침 틀
프로젝트 이름: [이름]
목적: [누구의 어떤 문제를 해결하는가]
사용자와 사용 상황: [대상, 장소, 기기]
현재 상태: [완료된 일과 남은 일]
이번 범위: [할 일과 제외할 일]
참고 자료: [최신 기준 문서와 실제 사용할 파일]
대화 역할: [요구사항 정리, 비교, 검토 등]
진행 방식: 질문 → 정리 → 작은 Pilot → 검증 → 개선
완료 기준: [어떤 결과를 확인하면 완료인가]
승인 기준: [외부 전송·공개·배포 전에 확인할 내용]

Pilot(시범 운영)은 원래 배를 항구로 안내하는 도선사를 뜻했고, 지금은 본격 도입 전에 작게 먼저 해 보는 시험을 말합니다.

3. 오래 유지할 것과 자주 바뀌는 것을 나눕니다

목적, 금지사항, 완료 기준처럼 오래 유지할 내용은 지침에 둡니다. 진행 상황처럼 자주 바뀌는 내용은 "최신 상태" 문서를 파일로 올려 관리합니다.

4. 기준 파일은 이름으로 지정합니다

"이전 자료 참고해"라고 하기보다 파일을 올리고 이름을 지정합니다. 버전이 여러 개라면 무엇이 최신인지 알려 줍니다.

  • 지식 파일은 프로젝트마다 분리됩니다. 다른 프로젝트의 파일은 그 프로젝트 안에서만 보입니다.
  • Claude: 프로젝트 메모리를 계정 전체 메모리와 연결할지, 완전히 분리할지 고를 수 있습니다. 프로젝트 안에서 예전 대화를 찾으면 그 프로젝트의 대화만 검색됩니다.
  • ChatGPT: 프로젝트에는 기본 메모리와 프로젝트 전용 메모리처럼 참조 범위가 다른 방식이 있습니다. 프로젝트 생성 시 선택한 메모리 범위를 확인하세요. 일반 Project는 내 PC 폴더를 직접 보지 않습니다. 데스크톱 앱의 로컬 프로젝트는 폴더를 연결할 수 있으니, 어떤 폴더가 연결됐는지 확인합니다.
08

앱 연결은 필요할 때

요구사항을 대화로 정리하는 데는 앱 연결이 필요 없습니다. 실제 자료를 확인해야 할 때 연결합니다.

Connector (연결기, 連結器) : Drive, Gmail, Notion, GitHub 같은 내 앱의 자료를 AI가 직접 읽도록 이어 주는 통로. ChatGPT에서는 "앱"이라고 부릅니다.
  • 연결한 앱과 사용자가 허용한 권한에 따라 접근할 수 있는 자료 범위가 달라집니다. 연결 전 권한과 접근 범위를 확인합니다.
  • 자료와 목적을 함께 지정합니다. 예: "Drive의 [문서 이름]에서 대상과 일정만 확인해 주세요."
  • 연결했다고 모든 자료를 확인한 것은 아닙니다. 어떤 자료를 읽었고 무엇을 확인했는지 보여 달라고 요청합니다.
  • 활용 예: Notion을 연결해 이력과 일정 데이터베이스를 조회하면, 메모리에 저장된 내용이 사실인지 대조할 수 있습니다.
09

넣지 말아야 할 것

지침과 메모리는 여러 대화에서 반복해 읽히므로, 노출되면 곤란한 정보와 충돌할 정보는 넣지 않습니다.

식별번호학번, 자격번호, 면허번호, 계좌번호
비밀 정보비밀번호, API Key, Token
다른 사람의 개인정보수강생, 고객, 가족의 연락처와 기록
앱 하나에만 쓰는 규칙해당 프로젝트 지침으로 보냅니다
이미 바뀐 예전 지침새 지침과 충돌합니다
같은 내용의 중복지침과 메모리 중 한 곳에만 둡니다
10

대화로 요구사항 만들기

처음부터 완성된 프롬프트를 쓸 필요는 없습니다. 내 말로 목적과 불편을 설명하고, 대화하며 조건을 채웁니다.

Prompt(프롬프트, 지시문)는 라틴어 promptus(앞으로 꺼내 놓은, 준비된)에서 왔습니다. 연극에서 배우에게 대사를 일러 주는 사람을 prompter라고 하듯, AI가 움직이도록 건네는 질문이나 요청을 말합니다.

요구사항 대화 시작
제가 하고 싶은 일은 [생각]입니다. 지금 불편한 점은 [문제]입니다. 먼저 요구사항을 정리하고 싶습니다.
제 생각을 짧게 정리해 보여 준 뒤, 결과를 바꿀 중요한 질문부터 하나씩 해 주세요.
이미 알려 준 것은 다시 묻지 말고, 아직 구현이나 외부 작업은 시작하지 마세요.
마지막에는 목적·사용자·입력·처리·출력·완료 기준으로 정리해 주세요.

대화는 이 순서로 발전합니다

생각 설명→AI가 이해한 내용 확인→빠진 조건 질문→첫 범위 선택→완료 기준 확인→요구사항 확정

AI가 이해한 내용을 먼저 확인하면, 방향이 어긋난 채로 구현하는 일을 줄일 수 있습니다. AI의 제안은 근거와 함께 검토하고, 실제로 써 본 결과를 보고 보완합니다.

요구사항은 여섯 칸으로 정리됩니다

목적왜 만드는가
사용자누가, 어디서 쓰는가
입력무엇을 넣는가
처리무엇을 판단·변환하는가
출력무엇을 받는가
완료 기준무엇을 보면 끝인가

이 여섯 칸이 채워진 문서가 Coding Agent에게 넘길 요구사항서가 됩니다.

바로 시작할 수 있는 예시

예시 1 · 수업 복습 도구
학생들이 수업 후 혼자 복습하기 어려워합니다. 수업 자료를 바탕으로 질문에 답하고, 이해한 부분을 확인하는 도구를 만들고 싶습니다.
먼저 한 차시를 Pilot으로 정리하고, 학생 수준·질문 범위·완료 기준을 저와 함께 정해 주세요.
예시 2 · 드론 영상 편집
여러 촬영 영상에서 쓸 장면을 골라 짧은 영상으로 만들고 싶습니다.
먼저 촬영 목적·대상 시청자·영상 길이·화면 비율을 확인해 편집 요구사항을 정리해 주세요.
원본을 수정하거나 업로드하기 전에 검토할 편집안을 보여 주세요.

대화 전·후 비교: 요구사항이 완성되는 모습

아래는 가상의 수업 복습 도구 예시입니다. 처음에는 막연한 생각뿐이지만, 질문과 답변을 거치면 Coding Agent에게 전달할 요구사항으로 구체화됩니다.

대화 전

"학생들이 집에서 복습할 수 있는 앱을 만들고 싶어요."

요구사항 항목대화 후 확정한 내용 (예시)
목적학생의 수업 복습 지원
사용자초등학교 5~6학년
입력강사가 등록한 한 차시의 학습 내용
처리5문항 퀴즈 출제·채점

완료 기준한 차시 Pilot에서 퀴즈·채점·결과 표시가 정상 작동

여섯 항목이 구체화되면 첫 Pilot을 구현하고, 실제 사용 결과를 바탕으로 수정·확대합니다.

11

설정 후 시험하기

설정을 마치면 짧은 질문 다섯 개로 확인합니다. 기대와 다른 항목은 관련 지침 한 줄만 고칩니다.

12

두 AI 함께 쓰기

두 서비스에는 비슷한 목적의 기능이 있지만, 지침·메모리의 저장 구조와 참조 범위, 연결 방식은 서로 다릅니다.

함께 쓸 때의 원칙

  • 두 AI에 같은 목적·대상·원본 자료·완료 기준을 줍니다.
  • 한쪽에서 고친 지침과 메모리는 다른 쪽에 자동으로 반영되지 않습니다. 각각 확인합니다.
  • 답이 다르면 어느 쪽이 맞는지보다 각 답의 근거와 빠진 조건을 비교합니다.
  • 최종 판단은 사람(Owner)이 합니다.
13

세 줄 요약

  1. 나에 대한 사실은 소개와 메모리에, 답변 방식은 지침에, 작업 기준은 프로젝트에 둡니다.
  2. 꺼내고, 대조하고, 확정한 뒤에 나누고, 두 AI에 똑같이 맞춥니다.
  3. 짧은 대화와 Pilot으로 시험하며 요구사항을 구체화하고, 최종 판단은 내가 합니다.
