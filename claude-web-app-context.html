Claude: 웹과 앱에서 무엇을 공유하고,
새 창에서 어떻게 이어 가나?

웹(claude.ai)과 앱(Claude Desktop)을 가로축으로, 대화하는 Claude(Claude 탭)와 코딩하는 Claude Code(Code 탭)를 세로축으로 구분해 2 × 2로 봅니다. 핵심 판단 기준은 ChatGPT 편과 같습니다. 내 PC 폴더에 직접 접근할 수 있는가?, 서로 대화와 작업 결과를 공유하는가?, 그리고 새 창에서 무엇을 읽고 이어 가는가?입니다.

표기 원칙: ‘웹·앱’, ‘Claude·Code’, ‘내 PC 폴더로 시작·Cloud로 시작’은 이 강연에서 쓰는 교육용 분류입니다. 괄호 안에 공식 문서의 이름을 적었습니다. 데스크톱 앱에는 Cowork라는 작업 화면도 있지만 이 자료에서는 다루지 않습니다. [관찰] 표시는 강연자가 실제로 써 보며 확인한 동작이고, 앱 버전이 바뀌면 달라질 수 있습니다.
Pro 이용 범위 기준 기능은 계정·앱 버전·권한에 따라 달라질 수 있음 짝 자료: ChatGPT 편

02 · 한눈에 보는 2 × 2 비교표

가로는 어디서 여는가(웹 브라우저 / PC에 설치한 앱), 세로는 어떤 Claude인가(대화하는 Claude / 코딩하는 Claude Code)입니다. ‘직접 접근’은 파일을 첨부하지 않아도 AI가 PC의 폴더를 열어 파일을 찾고, 고치고, 프로그램을 실행하는 것을 뜻합니다. 각 칸의 예시를 먼저 읽으면 이해가 쉽습니다.

구분
웹 (claude.ai)브라우저에서 사용
앱 (Claude Desktop)PC에 설치하여 사용
Claude채팅 (Claude 탭)
웹 · Claude

대화하는 Claude (Chat)

대화, 웹 검색, 올린 파일 분석, 아티팩트로 문서·화면 만들기.

PC 직접 접근 불가

예시: 엑셀 파일을 끌어다 놓고 “월별 합계를 표로 정리해 줘”라고 하면 정리해 줍니다. 하지만 “내 바탕화면의 보고서 폴더를 열어 봐”는 못 합니다. 파일을 직접 올려 줘야 합니다.

앱 · Claude

대화하는 Claude (Chat)

웹과 같은 대화에 더해, 대화를 시작할 때 PC 폴더 하나를 연결할 수 있습니다.

연결한 폴더 들여다보기만

예시 [관찰]: 데스크톱에서 H:\AI_Projects 폴더를 연결하고 “폴더 목록 보여 줘”라고 하면 보여 줍니다. 하지만 “이 프로그램을 실행해 봐”, “GitHub에서 내려받아 줘”는 못 합니다. PC에서 명령을 실행하는 손발이 없기 때문입니다.

CodeClaude Code
웹 · Code

클라우드에서 코딩하는 Claude (claude.ai/code)

Anthropic의 클라우드 컴퓨터가 GitHub 저장소를 가져와 코딩·테스트하고, 결과를 GitHub 브랜치로 올립니다.

PC 직접 접근 불가

예시: 출근길 휴대폰이나 다른 사람 컴퓨터의 브라우저에서 “타자 연습 앱에 순위표를 추가해 줘”라고 맡깁니다. 일은 클라우드에서 하고, 저녁에 집 PC에서 GitHub의 바뀐 코드를 내려받아(Pull) 확인합니다.

앱 · Code

내 PC에서 코딩하는 Claude (Code tab)

세션을 시작할 때 고른 내 PC 폴더에서 파일을 읽고 쓰고, 명령을 실행하고, 서버를 켜고, 앱 안 브라우저로 화면까지 확인합니다.

PC 직접 접근 가능

예시: H:\AI_Projects 폴더를 골라 “녹화 영상 세 편을 4K로 바꿔서 YouTube에 올려 줘”라고 하면, PC의 영상 파일을 직접 변환하고 올립니다. 이 자료를 만든 강연자의 하루 대부분이 이 칸입니다.

비고: 같은 Code 탭에서 세션을 시작할 때 폴더 대신 Cloud를 고르면, 그 세션은 왼쪽 ‘웹 · Code’와 같은 클라우드 세션이 되어 내 PC를 보지 못합니다. 아래 상자를 보세요.

앱 Code 탭의 갈림길: 세션을 시작할 때 무엇을 고르나
내 PC 폴더를 고르면

그 폴더 안에서 직접 일합니다. 예: H:\AI_Projects를 고르면 영상 변환, 파일 정리, 프로그램 실행까지 합니다. 그 PC가 켜져 있어야 합니다.

Cloud(저장소)를 고르면

창만 앱이고 일은 클라우드에서 합니다. 웹 Code와 같아서 내 PC 폴더는 못 봅니다. 예: PC를 꺼도 되는 긴 작업을 맡길 때.

선택은 세션마다

한 세션을 Cloud로 열었다고 앱 전체가 바뀌지 않습니다. 다음 세션을 다시 내 PC 폴더로 열면 다시 PC를 직접 다룹니다.

주의: ‘가능’은 Pro에서 해당 기능을 쓸 수 있는 경우를 뜻하며, 사용량 한도와 권한 설정의 영향을 받습니다. 휴대폰 앱의 Code 탭에서도 클라우드 세션을 열고 이어 볼 수 있습니다.

04 · 직접 연결할 수 없다면: GitHub 경유와 원격 조종

클라우드에서 코딩하고 PC와 결과를 맞추는 방법은 ChatGPT 편의 Codex Cloud와 같습니다. Claude에는 여기에 PC에서 도는 세션을 다른 기기에서 조종하는 길이 하나 더 있습니다.

① PC → GitHub

Code 탭 로컬 세션이나 내가 Commit·Push하면 GitHub에 이력이 남습니다.

② 클라우드에서 개발

클라우드 세션이 저장소를 받아 코딩·테스트하고 브랜치를 올립니다. Pull Request로 검토합니다.

③ GitHub → PC

PC에서 Pull해야 바뀐 코드가 들어옵니다. 클라우드에만 있는 파일은 PC에 자동으로 생기지 않습니다.

또 하나의 길, Remote Control: 데스크톱 앱의 로컬 세션에 Remote Control을 켜 두면, 휴대폰이나 다른 컴퓨터에서 그 세션에 지시를 보낼 수 있습니다. 파일을 옮기는 것이 아니라 이 PC에서 일하는 Claude에게 멀리서 말을 거는 것입니다. 그래서 그 PC가 켜져 있어야 합니다.

.env, API Key, DB 같은 Git에서 뺀 파일은 GitHub로 옮겨지지 않으므로 사람이 따로 옮깁니다.

예시로 읽기

예시 ① 채팅은 따라온다

데스크톱 앱의 Claude 탭에서 강연 줄거리를 이야기하다가 노트북 앱을 열면, 같은 대화가 그대로 있어 이어서 말할 수 있습니다. 웹 브라우저와 휴대폰에서도 같습니다.

예시 ② 폴더는 따라오지 않는다 [관찰]

그 대화는 데스크톱에서 시작하며 H:\AI_Projects를 연결했습니다. 노트북에서 같은 대화를 열어도 보이는 폴더는 데스크톱 것이고, 대화 안에서 노트북 폴더로 바꿀 수 없었습니다. 노트북 폴더를 보려면 노트북에서 새 대화를 열어야 하고, 새 대화는 앞의 대화 내용을 모릅니다.

예시 ③ Code 탭은 컴퓨터마다 따로

데스크톱 Code 탭에서 하루 종일 영상을 올렸어도, 노트북 Code 탭 목록에는 그 세션이 없습니다. 데스크톱의 기억 수첩(자동 메모리)도 노트북은 모릅니다. 같은 계정, 같은 앱이어도 그렇습니다.

예시 ④ 같은 앱의 두 탭도 서로 모른다

데스크톱 Claude 탭에서 정한 요구사항을, 같은 앱의 Code 탭은 저절로 알지 못합니다. 요구사항을 Notion이나 문서에 적고 “이 페이지 읽고 시작해”라고 해야 합니다.

예시 ⑤ 클라우드 세션은 어디서나

웹에서 시작한 Code 클라우드 세션은 앱에서 Cloud를 골라 열거나 휴대폰에서 열어도 같은 세션입니다. 내 PC 세션과는 대화가 아니라 GitHub의 코드로만 이어집니다.

예시 ⑥ 멀리서 말 걸기(Remote Control)

데스크톱 Code 세션에 Remote Control을 켜 두면, 밖에서 휴대폰으로 그 세션에 지시할 수 있습니다. 대화가 옮겨 가는 것이 아니라 데스크톱에서 일하는 Claude에게 멀리서 말을 거는 것이라, 데스크톱이 켜져 있어야 합니다.

핵심: 채팅 대화는 계정에 붙어 어디서나 이어지지만, 그 대화에 연결한 PC 폴더는 대화를 시작한 PC 것입니다. Code 탭은 세션마다, 그리고 컴퓨터마다 대화 기록과 작업 폴더가 따로 있습니다. ‘분리’는 자동 공유가 없다는 뜻이지, Notion·문서·GitHub로 직접 전달하는 것까지 막혀 있다는 뜻은 아닙니다. 그래서 강연자는 Notion 페이지 하나를 모두가 읽고 쓰는 다리로 씁니다.

06 · 무엇이 공유되는가? 대화와 파일을 구분

비교 대상대화 기록작업 파일·결과물 전달
웹 Claude ↔ 앱 Claude동기화대화에 첨부한 자료는 그 대화에서 이용. 연결한 PC 폴더는 시작한 PC에서만 [관찰].
Claude 탭 ↔ Code 탭기록 분리대화 본문 자동 전달 없음. Notion 페이지, 문서 파일, GitHub로 명시적으로 전달.
데스크톱 앱 Code ↔ 노트북 앱 Code기록 분리GitHub Push·Pull, USB, Notion 진행표로 전달. 자동 메모리 파일도 각 PC에 따로 있음.
웹 Code(클라우드) ↔ 내 PC 폴더같은 클라우드 세션은 이어 봄GitHub 브랜치로 받아 PC에서 Pull.

실전: 강연자의 Vibe Agent → Coding Agent 협업

채팅(Claude 탭, 토비): 문제와 요구사항을 대화로 확정하고 Notion 프로젝트 페이지에 기록
↓ 명시적으로 전달 (Notion 페이지 링크, 또는 GitHub의 project-intent.md)
Code 탭 로컬 세션: Notion과 저장소 문서를 읽고 내 PC에서 구현·테스트
↓ Commit·Push (승인한 파일만)
GitHub: 코드·문서 공유, 이력 관리
↓ 결과 기록
Notion 진행표: 확인 결과와 다음 할 일. 다음 채팅이 여기서부터 읽음
중요한 구별: Notion과 GitHub는 기록과 파일을 공유하는 수단이지, 채팅과 Code 탭의 대화 기록을 자동으로 합치는 수단이 아닙니다. 비밀 값과 개인정보는 어느 쪽에도 올리지 않습니다.

08 · Notion을 문맥 저장소로 설정하기 (강연자 실제 구성)

Context(문맥)는 다음 작업자가 이어서 판단하는 데 필요한 목표·결정·이유·미완료 사항입니다. ChatGPT 편과 같은 생각으로, ‘언제 읽을지’는 지침과 메모리에, ‘어디를 읽고 어떻게 적을지’는 Notion 시작 페이지에 적었습니다.

  1. 연결 확인. Claude 설정의 커넥터에서 Notion을 연결하고 승인합니다. 데스크톱 앱의 Code 탭도 같은 계정의 커넥터를 씁니다.
  2. 시작 페이지 하나. 작업 공간 최상위에 비공개 Claude 맥락 유지용 페이지를 만들고, 목차와 사용 규칙만 둡니다. 그 아래에 프로젝트 페이지를 하나씩 둡니다.
  3. 채팅 쪽 시작 규칙. claude.ai 프로젝트의 지침에 아래 문구를 넣습니다.
새 대화를 시작하면 Notion 「Claude 맥락 유지용」에서 이 프로젝트 페이지를 먼저 읽고, 현재 상태와 나에게 온 인계를 확인한 뒤 일해 주세요.
Notion에 새 페이지를 만들 때는 반드시 「Claude 맥락 유지용」 아래 이 프로젝트 페이지 밑에 만들고, 개인 페이지 맨 위(루트)에는 만들지 마세요.
대화를 마치거나 주제를 바꿀 때 이어 갈 내용이 있으면 저장할지 먼저 물어 주세요. 동의하면 프로젝트 페이지에 핵심만 반영하고 링크를 보여 주세요.
  1. Code 쪽 시작 규칙. Code 탭은 자동 메모리에 이정표 한 줄을 남깁니다. 예: 강연 이야기는 노션 「강연 마무리 진행표」부터 읽는다. 프로젝트 전체 규칙은 CLAUDE.md에 둡니다. 늘 같은 폴더(예: H:\AI_Projects)를 골라 세션을 시작해야 같은 메모리가 읽힙니다.

ChatGPT 편에서는 Notion 쪽 설정 가이드로 운영 가이드와 Memories가 만들어졌습니다. Claude 편의 시작 페이지는 강연자가 직접 만든 구조이며, Claude와 ChatGPT는 서로 다른 Notion 계정에 연결해 기록이 섞이지 않게 했습니다.

09 · 기록과 인계 작성하기

같은 주제는 여러 대화에서 다뤄도 같은 프로젝트 페이지를 갱신합니다. 페이지 맨 위에는 지금 유효한 것만 둡니다.

현재 상태 · 작성 예시 (강연준비_바이브코딩 첫걸음)
목표　11/10 강연, 11/9 리허설 전에 자료 확정
결정　오프닝 핵심 문장: "바이브코딩은 코드를 몰라도 되게 해 주지만, 일을 몰라도 되게 해 주지는 않습니다."
이유　청중 대부분이 업무 전문가(공무원·공공기관)이므로
다음 행동　업무 시연 영상(매출채권 → 재고 → 공매도 연령분석)
원본　[진행표 링크] · [보충자료 사이트 링크]

다른 창·다른 PC에 맡길 때는 공용 진행표에 한 줄로 남깁니다. 강연자는 노트북과 데스크톱의 Claude 넷이 이 형식으로 일을 나눴습니다.

M7 | 노트북 Claude 탭 → 데스크톱 Code 탭 | 요청 | 폴더 열두 개의 상태를 조사해 표로 적어 주세요 | 대기
M8 | 데스크톱 Code 탭 → 노트북 Claude 탭 | 결과 | 조사 표를 아래 9번에 적었습니다. 지울지는 주인님 결정 | 완료
  • 받은 쪽이 일을 맡으면 ‘진행’, 끝나면 ‘완료’와 결과 위치를 적습니다.
  • 에이전트는 스스로 깨어나지 않습니다. 사람이 그 창에 “진행표 읽고 나에게 온 대기 메시지 처리해”라고 한 줄 보내야 움직입니다. 받는 이를 적는 것만으로 다른 창에서 일이 시작되지는 않습니다.
  • 비밀 값(.env, API Key, 토큰)은 적지 않고 ‘있음/없음’만 적습니다.

10 · 페이지 정리 규칙

시작 페이지는 목차만, 프로젝트 페이지는 지금 필요한 것만

프로젝트 페이지 맨 위에는 목표, 유효한 결정, 열린 인계, 다음 행동만 둡니다. 끝난 단계와 긴 기록은 날짜가 붙은 하위 페이지로 내립니다. 결정이 바뀌면 맨 위를 고치고, 예전 결정은 하위 페이지에 날짜와 함께 남깁니다. 그래야 다음 창이 오래된 결정을 따라 하지 않습니다.

실제로 겪은 일: 루트에 페이지가 쌓였다

대화마다 Claude가 저장 위치 없이 페이지를 만들다 보니, 개인 페이지 맨 위에 Claude가 만든 페이지가 하나둘 흩어졌습니다. 사람이 만든 페이지와 섞여 찾기 어려워졌습니다. 그래서 흩어진 페이지를 프로젝트 아래로 옮기고, “루트에 만들지 않는다”를 시작 페이지 규칙·프로젝트 지침·Code 메모리 세 곳에 적었습니다. Notion 링크는 이름이나 위치가 아니라 고유 번호로 이어지므로 옮겨도 끊어지지 않습니다.

ChatGPT 편에는 매일 오전 9시 점검 예약이 있습니다. Claude도 데스크톱 앱의 예약 작업으로 비슷하게 할 수 있지만, 강연자 환경에는 아직 설정하지 않았습니다.

11 · 실습 · 새 대화에서 기록 찾아가기

두 개의 대화로 결정 하나가 실제로 전달되는지 확인합니다. 강의용 실습 절차입니다.

첫 번째 대화에서 저장

‘한글 타자 수업’의 결정은 같은 글쇠 20회 반복, 다음 글쇠는 학습자가 선택하는 것입니다. 다음 작업은 관찰 문항 두 개 작성입니다. 오늘은 여기까지.

저장할지 물으면 ‘네, 저장해 주세요’라고 답합니다. 받은 링크를 열어 시작 페이지 아래 프로젝트 밑에 저장됐는지, 두 결정과 다음 작업이 맞는지 확인합니다.

새 대화에서 이어 가기

한글 타자 수업을 이어 가요. Notion 「Claude 맥락 유지용」에서 이 프로젝트의 현재 상태를 확인하고, 오늘 할 일과 근거가 된 페이지 링크를 알려 주세요.

성공 기준　새 대화가 같은 프로젝트 페이지를 열고 ‘관찰 문항 두 개 작성’을 다음 작업으로 제시합니다. 첫 대화에서 받은 링크와 대조하세요. 찾지 못하면 링크를 직접 주고 열어 보게 해, 페이지 접근 문제인지 찾기 문제인지 가립니다.

Code 탭에서 한 번 더

같은 문장을 Code 탭의 새 세션에 보내 봅니다. 채팅과 Code 탭은 대화를 나누지 않지만, 같은 Notion 페이지를 읽으면 같은 다음 작업을 말해야 합니다. 이것이 Notion이 두 탭 사이의 다리라는 증거입니다.

13 · 강연용 설명 문장

“Claude도 ChatGPT와 같은 틀로 보겠습니다. 화면은 웹과 앱으로, 그 안에서 채팅과 Code 탭으로 나눕니다. 가장 중요한 차이는 AI가 내 PC 파일을 직접 열고 고치고 실행할 수 있는지입니다. 그것은 데스크톱 앱 Code 탭의 로컬 세션만 할 수 있습니다. 채팅은 같은 앱 안에 있어도 손발이 클라우드에 있어서, 연결한 폴더를 들여다보는 데서 그칩니다. 대화 동기화는 또 별개입니다. 채팅 대화는 웹·앱·노트북·데스크톱 어디서나 이어지지만, 대화에 연결한 PC 폴더는 시작한 PC 것입니다. 그리고 채팅과 Code 탭은 같은 앱이어도 서로의 대화를 모릅니다. 그래서 저는 Notion 시작 페이지 하나를 정해 두고, 채팅도 Code 탭도 노트북도 데스크톱도 모두 거기를 읽고 거기에 적게 했습니다. Code 탭에는 자동 메모리와 CLAUDE.md가 있어 새 세션마다 규칙과 이정표가 저절로 들어오지만, 그건 이 PC 안의 파일입니다. 결국 AI가 알아서 기억하는 것이 아니라, 사람이 기억할 곳과 읽는 순서를 정해 주는 것입니다.”
