ChatGPT: 웹과 앱에서 무엇을 공유하고,
새 창에서 어떻게 이어 가나?

웹(Web/Cloud)과 앱(Desktop)을 가로축으로, ChatGPT와 Codex를 세로축으로 구분합니다. ChatGPT는 다시 Chat / Work 두 탭으로 나눕니다. 핵심 판단 기준은 내 PC 폴더에 직접 접근할 수 있는가?와 서로 대화 및 작업 결과를 공유하는가?, 그리고 새 창에서 무엇을 읽고 이어 가는가?입니다.

표기 원칙: ‘웹·앱’, ‘ChatGPT·Codex 모드’, ‘Chat·Work 탭’은 이 강연에서 일관되게 사용하는 교육용 분류입니다. 공식 인터페이스의 정확한 구성 명칭과 완전히 일치한다고 주장하지 않습니다. 괄호 안에는 확인된 공식 기능명을 넣었습니다.
Plus 이용 범위만 수록 실제 기능은 계정의 배포 상태·권한에 따라 달라질 수 있음 짝 자료: Claude 편

02 · 한눈에 보는 2 × 2 비교표

ChatGPT 영역을 위아래로 나누었으므로 실제 설명 행은 Chat, Work, Codex 세 줄입니다. ‘직접 접근’은 파일 첨부나 별도 커넥터를 거치지 않고 PC의 선택된 폴더에 도구가 접근하는 것을 뜻합니다.

주의: ‘가능’은 Plus에서 해당 기능에 접근할 수 있는 경우를 뜻하며, 기능 활성화와 허용 범위는 배포·권한·사용량 제한의 영향을 받습니다.

04 · 직접 연결할 수 없다면: GitHub 경유

강연자의 바이브코딩 방식처럼 클라우드에서 코딩하고 로컬 PC와 결과를 동기화할 때 유용한 흐름입니다.

⇄

⇄

① PC → GitHub

내 PC에서 Commit하고 Push하면 GitHub에 변경 이력이 저장됩니다.

② Codex Cloud에서 개발

연결된 저장소를 읽어 클라우드에서 코딩·테스트 후 변경을 Commit·Push합니다(쓰기 권한 필요).

③ GitHub → PC

PC에서 Pull하여 변경을 가져옵니다. Cloud에만 남은 파일은 Push하지 않으면 PC에 자동으로 나타나지 않습니다.

GitHub를 통한 동기화는 자동적인 실시간 PC 폴더 접근이 아닙니다. 연결된 저장소의 권한·브랜치·Commit·Push·Pull이 필요합니다. DB와 비밀키 등 Git 관리에서 제외된 데이터는 별도로 보존합니다.

05 · 여섯 환경 사이의 대화 기록 공유 관계

질문: 한 환경에서 대화를 시작하고 다른 환경으로 이동했을 때, 같은 대화가 보이고 이어서 사용할 수 있을까요? 아래 표는 같은 Plus 계정을 전제로 합니다. 각 칸은 ‘행 → 열’ 사이의 관계이며 양방향으로 읽을 수 있습니다.

환경웹 Chat웹 Work웹 Codex앱 Chat앱 Work앱 Codex
웹 Chat같은 환경자기 대화기록 통합자동 문맥 공유 아님분리자동 공유 안 됨동기화같은 Chat 대화기록 통합자동 문맥 공유 아님분리자동 공유 안 됨

앱 Work기록 통합자동 문맥 공유 아님조건부 동기화Cloud 작업에 한함분리자동 공유 안 됨기록 통합자동 문맥 공유 아님같은 환경자기 대화분리자동 공유 안 됨
앱 Codex분리자동 공유 안 됨분리자동 공유 안 됨조건부 동기화Cloud 작업에 한함분리자동 공유 안 됨분리자동 공유 안 됨같은 환경자기 대화
동기화: 같은 대화 이어가기기록 통합/조건부: 범위 주의분리: 자동 공유 없음
핵심: ‘기록 통합’은 Chat과 Work의 대화가 Recents(최근 항목)에 함께 표시된다는 뜻입니다. 서로 다른 두 대화가 본문 전체를 자동으로 읽거나 기억한다는 뜻이 아닙니다. 또한 ‘분리’는 자동 대화 기록 공유가 없다는 뜻이지, 사용자가 복사·첨부·공유 링크 등으로 내용을 전달하는 것까지 불가능하다는 뜻은 아닙니다.

조건부 동기화: Cloud Work는 웹↔앱에서 대화를 이어갈 수 있으나 Local Work는 동기화 설정 및 생성 시점에 따라 달라질 수 있습니다. Codex Cloud 작업은 웹↔앱에서 이어갈 수 있으나 앱 Codex의 로컬 작업을 동일하게 취급하면 안 됩니다. Plus 기능 배포 상태 및 권한에 따라 달라질 수 있습니다.

06 · 무엇이 공유되는가? — 대화와 파일을 구분

비교 대상대화 기록작업 파일·결과물 전달
웹 Chat ↔ 앱 Chat동기화대화에 첨부한 자료는 해당 대화에서 이용. PC의 다른 파일을 자동으로 공유하는 것은 아님.
웹 Work ↔ 앱 WorkCloud는 동기화Cloud Work 산출물은 연결된 작업에서 이어서 활용 가능. 앱의 로컬 실행 폴더는 웹 Work가 직접 열 수 없음.
Chat ↔ Work (웹/앱)최근 목록 통합Chat과 Work는 같은 ChatGPT 영역이지만 별개의 대화는 자동으로 본문을 공유하지 않음. 같은 프로젝트의 컨텍스트는 설정에 따라 활용 가능.
웹 Codex Cloud ↔ 앱 Codex같은 Cloud 작업은 가능동일 Cloud 작업을 이어갈 수 있음. 앱 Local 작업과는 구분하며 GitHub를 통한 소스 코드 전달 가능.
ChatGPT ↔ Codex (웹/앱)기록 분리대화 본문 자동 전달 없음. GitHub 저장소, 파일 첨부, 복사한 작업지시서 등으로 명시적 전달 가능.
Codex Cloud ↔ 내 PC 폴더PC와 직접 연결 아님GitHub로 Commit·Push 후 PC에서 Pull, 또는 파일 내보내기 등으로 결과물 전달.

실전: 강연자의 Vibe Agent → Coding Agent 협업

웹/앱 ChatGPT (Chat·Work) — 문제·요구사항 협의 및 project-intent.md 확정
↓ 명시적으로 전달 (GitHub에 승인된 문서 반영 또는 파일 전달)
웹/앱 Codex — 저장소와 지침 문서를 읽고 구현·테스트
↓ Commit·Push (승인된 파일만)
GitHub — 코드·문서 공유 / 이력 관리
↓ Pull 또는 연결 저장소 읽기
내 PC / ChatGPT Work — 결과물 검토 및 피드백
중요한 구별: GitHub는 파일과 커밋 이력을 공유하는 수단이지, ChatGPT와 Codex의 채팅 기록을 자동 통합하는 수단은 아닙니다. 비밀키, 개인 정보, 내부 채팅·로그 등은 올리기 전 제외해야 합니다.

예시: Chat에서 정하고 Work에서 만들기

예시 과제는 ‘반복 연습에 지친 학생도 따라 할 수 있는 한글 기본자리 수업’입니다. Chat에서 대상과 성공 조건을 정한 뒤, Work에 확정한 요구와 사용할 자료를 건넵니다.

① Chat에서 수업 의도 확정

한국어 초급 학습자에게 한글 기본자리를 가르치고 싶어요. 수업안을 바로 쓰기 전에 대상과 성공 조건부터 한 가지씩 물어봐 주세요.

② Work에서 결과물 만들기

확정한 요구사항은 ‘같은 글쇠 20회 반복, 다음 글쇠는 학습자가 선택’입니다. 이 기준으로 강사가 인쇄할 한 페이지 수업안을 만들어 주세요. 연습 절차와 관찰할 점을 넣어 주세요.

③ 실제 결과 확인

파일을 열고 ‘20회 뒤 자동으로 다음 글쇠로 넘어간다’는 내용이 들어갔는지 살펴봅니다. 발견하면 해당 문장을 지목하고, 다음 글쇠를 학습자가 선택하도록 고쳐 달라고 합니다.

07 · 세션 간 문맥 유지: Projects · Memory · Notion · GitHub

질문: 새 채팅을 만들어도 이전 프로젝트의 의도·결정·진행 내용을 이어 갈 수 있을까요? ChatGPT Plus에는 Projects, Memory, 연결 앱(Notion 포함)이 있습니다. Codex의 AGENTS.md와 GitHub는 다른 방식으로 이 문제를 해결합니다.

구분 기준: ① 대화 기록 동기화 = 같은 대화를 다른 화면에서 보기, ② 문맥 참조 = 다른 채팅의 관련 내용을 응답에 활용, ③ 외부 지식 보관 = 요약·결정 문서를 별도 저장소에 저장해 다시 읽기. 셋은 서로 다른 기능입니다.

ChatGPT Projects
(프로젝트)		프로젝트의 채팅·첨부 파일·프로젝트 지침·저장한 응답가능 — 동일 프로젝트 안의 관련 이전 대화·파일을 참조할 수 있음아니요 — Codex의 독립된 대화 기록으로 자동 복제되는 기능은 아님이전 대화의 모든 문장을 매번 정확하게 복원한다는 보장은 없음. Project-only memory에서는 프로젝트 외부 맥락을 분리하고 Work를 사용할 수 없음
ChatGPT Memory
(메모리)		ChatGPT가 개인화에 활용하는 관련 요약·선호·정보가능 — 활성화 및 접근 범위에 따라 관련 사실을 참조보장되지 않음 — Codex용 공통 지침 파일을 대신하지 않음전체 대화 전문이나 결정 기록을 정확히 저장하는 버전 관리 저장소가 아님
Notion 연결

08 · Notion을 문맥 저장소로 설정하기 (강연자 실제 구성)

Context(문맥)는 다음 작업자가 이어서 판단하는 데 필요한 목표·결정·이유·미완료 사항입니다. 이번 설정에서는 맞춤 지침에 ‘언제 읽을지’를 적고, Notion 운영 가이드에 ‘어디를 읽고 어떻게 기록할지’를 적었습니다.

  1. 연결 확인. ChatGPT에서 Notion 앱을 선택하고 연결을 승인합니다. 이미 연결했다면 자신의 작업 공간 이름과 읽을 수 있는 페이지 하나를 확인합니다.
  2. 설정 방식 선택. 이번 사례에서는 Notion 설정 안내에서 ‘공유 문맥 설정’을 선택했습니다. 비공개 운영 가이드와 선호 기록용 Memories가 마련됐습니다.
  3. 저장 위치 지정. 작업 공간 최상위에 비공개 ChatGPT 페이지를 만들고, 그 아래에 주제별 페이지를 두도록 지정했습니다. 운영 가이드는 기존 ‘Documents · 에이전트 문서’에 두고 고유 링크로 연결했습니다.
  4. 시작 규칙 등록. ChatGPT 설정의 개인 맞춤 설정 → 맞춤 지침에 아래 문구를 추가합니다. 대괄호 자리에 자신의 운영 가이드에서 복사한 링크를 붙여 넣습니다.
새 채팅의 첫 작업 지시와 같은 채팅의 새 작업 지시마다 아래 Notion 운영 가이드를 먼저 읽어 주세요. 해당 주제의 현재 상태와 자신에게 온 인계를 확인한 뒤 작업해 주세요.
운영 가이드: [내 Notion 운영 가이드 링크]
대화를 마치거나 주제를 바꿀 때 이어갈 내용이 있으면 저장할지 먼저 물어 주세요. 동의하면 기존 기록에 핵심만 반영하고 다시 열어 확인한 뒤 링크를 보여 주세요.

10 · 페이지 길이와 매일 점검

상위 페이지에는 지금 필요한 내용만

목표, 현재 유효한 결정, 열린 인계, 다음 행동을 맨 위에 둡니다. 예컨대 연습 횟수가 바뀌면 현재 상태의 횟수를 고치고, 지난 결정을 대체한 날짜와 근거를 연결합니다. 그래야 다음 창이 오래된 수치를 채택하는 일을 줄일 수 있습니다.

긴 회의 내용이나 끝난 단계는 ‘ChatGPT → 한글 타자 수업 → 11월 11일 · 시범 수업’처럼 날짜와 단계명이 있는 하위 페이지에 기록합니다. 상위에는 요약과 링크를 둡니다. 대화 전문이나 인증정보는 저장 대상에서 제외합니다.

11 · 실습 · 새 채팅에서 기록 찾아가기

두 개의 채팅을 이용해 결정 하나가 실제로 전달되는지 확인합니다. 아래는 강의용 실습이며, 이번 설정에서 별도로 재현을 마친 결과는 아닙니다.

첫 번째 채팅에서 저장

‘한글 타자 수업’의 결정은 같은 글쇠 20회 반복, 다음 글쇠는 학습자가 선택하는 것입니다. 다음 작업은 관찰 문항 두 개 작성입니다. 오늘은 여기까지.

저장할지 물으면 ‘네, 저장해 주세요’라고 답합니다. 받은 링크를 열어 위치와 두 결정, 다음 작업이 맞는지 확인합니다.

새 채팅에서 이어가기

한글 타자 수업을 이어가요. Notion에서 현재 상태를 확인하고 오늘 할 일과 근거가 된 페이지 링크를 알려 주세요.

성공 기준　새 채팅이 같은 주제 페이지를 열고 ‘관찰 문항 두 개 작성’을 다음 작업으로 제시합니다. 첫 창에서 받은 링크와 대조하세요. 찾지 못하면 저장된 페이지 링크를 새 창에서 직접 열어 보게 해, 페이지 접근 문제인지 주제 검색 문제인지 확인합니다.

13 · 강연용 설명 문장

“저는 화면을 웹과 앱으로 구분하고, 그 안에서 ChatGPT와 Codex를 구분하겠습니다. ChatGPT는 다시 Chat과 Work로 나누겠습니다. 가장 중요한 차이는 AI가 내 PC 파일을 직접 열고 수정할 수 있는지입니다. 웹에서 작업할 때는 PC 폴더에 직접 접근하지 못하므로 파일을 첨부하거나 GitHub 같은 클라우드 저장소를 거칩니다. 대화 동기화는 또 별개입니다. 웹과 앱의 Chat 대화는 이어지며 Cloud Work도 동기화됩니다. 반면 Codex의 대화 기록은 ChatGPT와 분리되어 있으므로, 두 Agent가 협업할 때는 문서와 GitHub를 통해 작업 내용을 명시적으로 전달해야 합니다. 반대로 데스크톱 앱의 Work 또는 Codex에서 로컬 작업을 선택하고 접근을 허용하면 내 PC의 폴더를 직접 다룰 수 있습니다. 또한 새로운 세션에서 맥락을 이어갈 때는 ChatGPT Projects와 Memory를 사용할 수 있고, Notion·Google Drive처럼 연결한 지식 저장소의 문서를 읽게 할 수도 있습니다. 다만 ChatGPT와 Codex가 서로의 모든 채팅을 자동 공유하거나 Notion을 매번 자동 갱신하는 기능으로 설명하면 안 됩니다. 중요한 결정과 구현 지침은 GitHub 문서와 AGENTS.md처럼 명시적으로 기록·관리해야 합니다.”
