Agent Collab Kit
여러 AI 에이전트를 한 팀으로 묶는 협업 하네스

AI 에이전트 여럿에게 일을 맡기기 전에, 누가 무엇을 하고 어디에 기록하는지부터 정해 두는 파일 묶음입니다.

01왜 필요한가

에이전트 하나와 대화할 때는 문제가 잘 보이지 않습니다. 그런데 기획하는 AI, 개발하는 AI, 검사하는 AI가 함께 일하기 시작하면 다음과 같은 혼란이 생깁니다.

협업 구조가 없을 때 생기는 일Kit이 해결하는 방법
새 대화창을 열면 AI가 앞의 내용을 잊는다파일이 기억한다. 의도·상태·결정을 파일에 남겨 어느 AI든 읽고 이어간다
작업을 맡겨 놓고 누가 무엇을 하는지 몰라 우왕좌왕한다역할을 미리 정한다. 작업마다 책임자(총괄)는 한 명
만든 AI가 스스로 검사하면 자기 실수를 놓친다기획·개발·검사를 나눈다. 만든 쪽과 검사하는 쪽이 다르다
사람이 긴 보고서를 이 AI에서 저 AI로 옮기다 지친다내용은 파일로 주고받는다. 사람은 "지니, 시작해" 같은 짧은 신호만 전한다
내부 대화·비밀 정보가 공개 저장소에 섞여 나간다공개 직전에 점검한다. 내부 문서는 공개 대상에서 뺀다

핵심 생각

"Chat이 기억하게 하지 말고, Project가 기억하게 하자." 대화창은 언젠가 닫히지만, 파일은 남습니다. 이것을 Context Externalization(맥락 외부화, 脈絡 外部化)이라고 부릅니다. 머릿속 맥락을 밖으로 꺼내 파일에 적어 둔다는 뜻입니다.

02하네스라고 불러도 되는가

Harness(하네스, 馬具 마구): 원래는 말에 씌워 말의 힘을 수레에 전하고 방향을 잡아 주는 장비입니다. 힘은 말에게서 나오지만, 그 힘이 엉뚱한 곳으로 흩어지지 않게 묶어 주는 것이 하네스입니다.

AI에서는 "Agent = Model + Harness"라고 말합니다. 모델이 말이라면, 모델이 실제로 일하도록 둘러싼 지침 파일·도구·작업 순서·인계 방식이 하네스입니다.

정리하면 두 층이 있습니다.

층예하는 일
실행 하네스Claude Code, Codex 같은 프로그램AI 하나가 파일을 읽고 쓰고 명령을 실행하게 한다
협업 하네스Agent Collab Kit여러 AI가 같은 규칙·기록·순서로 한 팀처럼 일하게 한다

AGENTS.md 같은 지침 파일과 에이전트 사이의 인계 방식도 하네스의 일부로 봅니다. 그래서 이 Kit을 "협업 하네스"라고 부르는 것은 맞는 표현입니다.

03누가 함께 일하는가

이름도구맡는 일
Owner (나)—목표를 정하고, 짧은 신호를 전하고, 마지막에 직접 테스트하고 수락한다
토비ChatGPT 채팅 · Claude 채팅나와 대화해 의도를 정리하고, 결과가 내 의도와 맞는지 검토한다 (Vibe Agent)
행크 / 버디IDE의 Codex 확장 / Claude Code 확장시스템 기획, 작업지시서 작성, 개발 결과 검수 (작업마다 한 명이 총괄)
지니Antigravity IDE 기본 에이전트구현 계획을 세우고, 난이도에 따라 CLI와 모델을 골라 순서대로 일을 맡긴다
애니 · 토디 · 제리Antigravity CLI · Codex CLI · Claude Code CLI실제 코드 작성, 시험, 검토

에이전트 사이에 상하 관계는 없습니다. 서로 주고받는 문서는 지시하는 말투가 아니라 상대를 존중하는 말투로 씁니다.

04일이 흘러가는 순서

  1. 의도 확정나와 토비가 문제와 해결 방향을 PROJECT_INTENT.md에 확정한다
  2. 시스템 기획총괄(행크 또는 버디)이 개략 기획서 → 실전 기획서를 쓰고, 단계마다 토비가 검증한다. 내가 구현을 승인한다
  3. 구현 계획총괄이 작업지시서를 쓰고, 지니가 구현 계획서를 쓴다. 총괄이 기획과 맞는지 검토한다
  4. 순차 구현지니가 CLI에게 한 번에 한 작업씩 맡기고, 각 CLI는 완료 보고서를 남긴다
  5. 검수와 수락총괄 검수 → 토비 검토 → 내가 직접 테스트하고 수락한다. 문제가 있으면 그 단계에서 다시 고친다

05파일별 역할과 기록 방법

파일 안의 세부 형식은 몰라도 됩니다. 각 파일이 무엇을 위한 것인지만 알면 됩니다.

06꼭 지키는 다섯 가지

  1. 파일로 소통한다. 사람은 내용 판단 없이 짧은 신호만 전한다.
  2. 총괄은 한 명이다. 어려운 문제는 다른 에이전트의 검토를 받아 총괄이 최종 판단한다.
  3. 만드는 쪽과 검사하는 쪽을 나눈다. 개발 CLI는 기획자의 대화를 이어받지 않고 새 대화로 시작한다.
  4. 서로 존중한다. 에이전트 사이에 상하 관계가 없다.
  5. 공개 직전에 점검한다. 내부 문서·비밀 정보는 공개 저장소에 올리지 않는다.

07세 줄 요약

  1. AI 여럿에게 일을 맡기려면, 먼저 역할·순서·기록 위치를 정한 협업 하네스가 필요합니다.
  2. 의뢰서(INTENT)·현황판(STATE)·결정 장부(DECISIONS)·인계 쪽지함(handoffs)이 대화창 대신 기억합니다.
  3. 사람은 목표를 정하고 신호를 전하고 마지막에 수락하며, 나머지는 파일 위에서 AI들이 이어갑니다.
