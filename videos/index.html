0:00AI 여섯의 자리 만들기

  • 목표: Antigravity IDE 하나 안에서 여러 AI가 역할을 나눠 일하게 하기.
  • 알아 두면 좋은 말
    • IDE: 코드를 쓰고 실행하는 작업 프로그램. Antigravity는 Google이 만든 AI 중심 IDE.
    • 확장 프로그램: IDE에 기능을 더하는 추가 부품. 여기서는 Codex와 Claude Code를 IDE 옆 창으로 넣는다.
    • CLI(명령 도구): 같은 AI를 터미널에서 글자 명령으로 부르는 버전.

0:22토비에게 설치 안내 맡기기

  • 내가 한 일 화면을 캡처해 Claude 데스크톱 앱(토비)에 보냄. 버튼은 직접 누름.
  • AI가 한 일 캡처를 보고 "다음은 이 버튼"을 알려 줌. 비슷한 이름의 다른 앱이 아니라 독립 실행형(Standalone) IDE를 받으라고 짚어 줌.
  • 핵심 AI는 화면을 보고 안내하고, 실제 클릭과 로그인은 사람이 한다. 이 역할 나누기가 끝까지 이어진다.

1:36Google 로그인과 첫 설정

  • 화면 색, 에이전트 작업 방식, 함께 쓸 Google 도구, 보안 안내를 차례로 고름.
  • 2:12 에이전트 방식: "중요한 단계마다 내가 검토"(Review-driven)를 고름. 토비가 네 가지 차이를 설명.

2:55행크: Codex 확장 프로그램

  • 내가 한 일 "codex" 검색, 설치, ChatGPT 계정으로 로그인.
  • AI가 한 일 이름이 비슷한 확장 프로그램 중 게시자(openai)와 다운로드 수로 공식 제품을 가려 줌.
  • 알아 두면 좋은 말 Codex는 내 ChatGPT 요금제 한도를 쓴다.

4:48버디: Claude Code 확장 프로그램

  • 내가 한 일 같은 방법으로 설치, Anthropic 게시자 확인, 브라우저에서 Claude 계정 승인.
  • 정리 기본 에이전트 지니까지 IDE 안에 AI가 셋이 된다.

6:23애니·토디·제리: 터미널 명령 도구 세 개

  • 내가 한 일 토비가 준 공식 설치 명령을 터미널에 붙여 넣고 결과를 캡처.
  • AI가 한 일 빨간 경고 글자가 실제 오류가 아니라고 풀어 주고, 경로 등록 명령과 세 도구 버전 확인 명령(agy --version; codex --version; claude --version)을 만들어 줌.
  • 알아 두면 좋은 말 경로(PATH) 등록은 프로그램 이름만 쳐도 어느 폴더에서나 실행되게 컴퓨터에 위치를 알려 두는 일.

8:36자리 정리

IDE에는 지니, 옆 창에는 행크와 버디, 터미널에는 애니·토디·제리. 계획과 안내는 토비, 결정은 Owner.

9:04지니의 버튼이 없다

  • 내 요구 행크와 버디처럼 지니도 버튼으로 바로 누르게 해 달라.
  • AI의 답(토비): 나는 IDE 화면을 직접 바꿀 수 없다. IDE 안의 지니에게 맡기는 게 맞다.
  • 핵심 AI마다 손댈 수 있는 범위가 다르다. 정한 역할 배치는 Notion 기록에 남겨 다음 대화에서도 이어지게 한다.

10:00지니가 내장 버튼 켜기

  • 내가 한 일 다른 에이전트에게 물어 버튼이 IDE에 이미 내장된 기능이라는 것을 알고 지니에게 알려 줌.
  • AI가 한 일(지니): 설정을 켜고 창을 새로 고쳐(Reload Window) 오른쪽에 에이전트 버튼을 바로 보이게 함.

⚠ 영상을 열면 먼저 화질을 1080p로 바꿔 주세요

⚠ 영상을 열면 먼저 화질을 1080p로 바꿔 주세요

화면을 녹화한 영상이라 YouTube가 자동으로 고르는 화질(720p 이하)에서는 글씨가 뭉개져 읽을 수 없습니다. 1080p로 바꾸면 글씨가 또렷하게 보입니다.

화질 바꾸는 방법 (눌러서 보기)
  1. 컴퓨터: 영상을 재생하고 화면 오른쪽 아래 ⚙ 설정 → 화질 → 1080p HD를 누릅니다. 화질 옆에 "자동 (720p)"처럼 보이면 아직 바꾸지 않은 것입니다.
  2. 휴대폰 YouTube 앱: 영상 화면을 한 번 누르고 위쪽 ⚙ → 화질 → 고급 → 1080p를 고릅니다.
  3. 가능하면 전체 화면으로 보세요. 작은 창에서는 글씨가 더 작아집니다.

이 영상으로 전하고 싶은 것

이제는 누구나 자기 일을 대신해 주는 에이전트를 가질 수 있는 시대입니다. 이 영상에 나오는 프로그램 네 개는 모두 코딩을 배우지 않은 사람이 만들었습니다. 한 일은 하나입니다. 무엇을 원하는지 정확하게 정의하고, 그것을 코딩 에이전트에게 전달한 것입니다.

  • 매일 보는 YouTube 영상을 요약해 쌓아 두고 싶다 → 지식 도서관
  • 영어 문장을 따라 말하며 연습하고 싶다 → 영어 쉐도잉
  • 내가 정한 규칙대로 매일 아침 주문을 넣고 싶다 → 투자 에이전트
  • 매일 아침 필요한 정보를 메일로 받아 보고 싶다 → 이메일 에이전트

"이런 게 있으면 좋겠다"는 생각이 요구사항이 되고, 요구사항이 에이전트가 됩니다. 여러분의 일 중에도 매일 반복되는 일, 하나씩 확인하려면 엄두가 나지 않는 일이 있다면, 그것이 여러분의 첫 번째 에이전트가 될 수 있습니다.

Skyview: 나만의 에이전트 네 개가 모인 곳

Skyview는 제가 운영하는 웹 사이트입니다. 겉으로는 드론 영상을 보여 주는 사이트이지만, 관리자(Admin)로 로그인하면 나만 쓰는 버튼들이 나옵니다. 버튼을 누르면 내 컴퓨터에 있는 에이전트 프로그램이 바로 열립니다.

  • 웹 사이트는 인터넷에 있고, 에이전트는 내 컴퓨터에 있습니다. 이 둘을 잇기 위해 Windows에 "이 주소(tony-library:// 같은)가 오면 이 프로그램을 열어라"라고 등록해 둡니다.
  • 그래서 사이트 주소를 알아도 다른 사람은 버튼을 눌러도 아무 일도 일어나지 않습니다. 프로그램은 내 컴퓨터에만 있기 때문입니다.
  • 영상 1:48~6:51은 이 연결을 새 컴퓨터에 다시 만드는 장면입니다. 관리자 버튼만 열리고 나머지가 안 열리는 문제를, Claude가 고치기 전에 원인부터 진단하게 해서 해결합니다.

Claude 데스크톱 앱에는 Claude 탭과 Code 탭이 있습니다. 같은 앱, 같은 Claude처럼 보이지만 일하는 곳과 손발이 다릅니다. 이 차이를 모르면 "왜 이건 되고 저건 안 되지?"에서 막힙니다. 이 영상은 노트북과 데스크톱의 작업 폴더를 맞추는 실제 일을 하면서 그 차이를 하나씩 확인한 기록입니다.

이 영상으로 전하고 싶은 것

왜 만드나: 강의자료를 고칠 때마다 생기는 세 가지 손해

생성형 AI에게 강의자료를 만들어 달라고 하면 금방 그럴듯한 HTML이 나옵니다. 그런데 꼭 10~20%는 내 말과 다릅니다. 대화창에서 "이 문장만 고쳐 줘"라고 하면 AI는 파일 전체를 다시 써 줍니다. 그래서

  • 기다리는 시간이 파일 길이만큼 걸리고,
  • 고쳐 달라고 하지 않은 곳이 바뀌거나 긴 파일 뒤가 잘리고,
  • 다 고친 자료는 폴더 어딘가에 흩어져 다음 강의 때 다시 쓰기 어렵습니다.

무엇을 만드나: 고친 만큼 쌓이는 나만의 지식 저장소

  • ① 가져오기: 마음에 드는 강의자료 HTML을 넣으면, 원본은 그대로 보관하고 장면(section) 단위로 나눕니다. 문장은 한 글자도 바꾸지 않았는지 프로그램이 검사합니다.
  • ② 다듬기: 장면 번호나 문장을 말로 지목해 "이렇게 바꿔 줘"라고 하면 그 부분만 고쳐집니다.
  • ③ 덧붙이기: "이 장면에 터미널이 왜 터미널인지 넣고 싶어"처럼 대충 말하면, AI가 사실을 확인해 짧은 요약(발표용)과 자세한 스크립트(읽기용)로 나눠 씁니다.
  • ④ 확정: 장면마다 분야·주제·용어 꼬리표(메타태그)를 붙여 데이터베이스에 버전으로 쌓고, 공개 사이트에서 분류로 둘러보고 검색할 수 있게 합니다.
  • ⑤ 조립 (다음 단계): 새 강의 주제와 대상을 말하면, 이미 쌓아 둔 내 장면을 찾아 내 스타일로 새 강의자료를 엮습니다.

비유하면 파일 통째로 저장하는 것은 신문을 통째로 쌓아 두는 것이고, 장면 단위로 저장하는 것은 기사를 오려 주제별 스크랩북에 꽂아 두는 것입니다. 한 번 고친 문장, 한 번 덧붙인 설명이 다음 강의의 재료가 됩니다.

왜 대화창이 아니라 IDE인가

부분 수정은 AI의 말솜씨가 아니라 파일을 고치는 도구가 있는 환경이 만드는 능력입니다. 대화창 AI는 파일을 다시 써서 돌려주는 수밖에 없지만, IDE(Antigravity)의 코딩 에이전트는 내 컴퓨터의 파일에서 그 줄만 고치고, 프로그램을 실행해 확인하고, 데이터베이스에 저장할 수 있습니다. 동기는 "AI가 못 해서"가 아니라 "고치는 과정과 결과가 내 것으로 쌓이게 하려고"입니다.

  • AI는 내 말을 평균적인 뜻으로 알아듣는다: 사람만 아는 맥락은 말해야 전달됩니다. 그래서 중요한 기준은 정하기 전에 묻게 하고, 정한 것은 Notion과 의도 문서(PROJECT_INTENT.md)에 남겨 모든 에이전트가 같은 기준으로 일하게 했습니다.
  • 사람은 처음과 끝에서 결정만 한다: 기획 검토·구현·검사 에이전트가 상태 파일과 인수인계 문서로 일을 넘기고, 자동 테스트(82개)를 통과할 때까지 스스로 고칩니다. 사람은 처음에 의도를 승인하고, 끝에 결과를 확인합니다.
  • 테스트 통과가 끝이 아니다: 테스트는 모두 통과했지만 실제 강의자료로는 아직 시험하지 않았다는 점을 사람이 짚었습니다. 실제 자료를 넣자 장면 10개로 나뉘고 원본 보존 검사도 통과했지만, 화면이 원본보다 밋밋해 보였습니다.
