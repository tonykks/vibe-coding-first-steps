⚠ 영상을 열면 먼저 화질을 1080p로 바꿔 주세요

화면을 녹화한 영상이라 YouTube가 자동으로 고르는 화질(720p 이하)에서는 글씨가 뭉개져 읽을 수 없습니다. 1080p로 바꾸면 글씨가 또렷하게 보입니다.

화질 바꾸는 방법 (눌러서 보기)
  1. 컴퓨터: 영상을 재생하고 화면 오른쪽 아래 ⚙ 설정 → 화질 → 1080p HD를 누릅니다. 화질 옆에 "자동 (720p)"처럼 보이면 아직 바꾸지 않은 것입니다.
  2. 휴대폰 YouTube 앱: 영상 화면을 한 번 누르고 위쪽 ⚙ → 화질 → 고급 → 1080p를 고릅니다.
  3. 가능하면 전체 화면으로 보세요. 작은 창에서는 글씨가 더 작아집니다.

43:02▶ 영상 보기

외국인 유학생용 3개 언어 강의 사이트를 수업 전날 밤에 고친다. 대화창의 Claude가 요구 사항과 원고를 쓰고 Code 탭의 Claude가 파일을 고쳐 검사·보고하며, 사람은 결정과 승인만 하는 분업 방식을 만들어 간다.

장면별 자세한 설명

0:00작업 범위 정하기

  • 내 요구 내일 9시 수업 전에 강의 사이트를 고치자. 무엇부터 할지 정해 달라.
  • AI가 한 일 19개 페이지를 읽고 "언어 기억, 공통 디자인 파일(course.css), 탭 제목 맞추기"로 첫 범위를 제안. 내가 결정할 질문(수업 시간 표기, TOPIK 등급)은 따로 모아 물음.
  • 알아 두면 좋은 말 CSS 파일은 글꼴·색·배치 같은 디자인 규칙을 모아 둔 파일. 하나로 모으면 한 곳만 고쳐도 모든 페이지가 같이 바뀐다.

1:45번역 빠진 곳 찾기

  • 내가 한 일 미얀마어 화면을 캡처해 보냄.
  • AI가 한 일 화면을 하나씩 보는 대신 자동 검사 프로그램을 돌려 번역이 빠진 곳을 모두 찾아 채움.

3:30"더 빠른 방법 없나?" (이 편의 핵심 장면 ①)

  • 내 요구 하나씩 고치는 속도가 너무 느리다.
  • AI의 답 데스크톱 대화창보다 Code 탭이 빠르다. 파일을 바로 고치고 브라우저로 결과를 직접 확인할 수 있기 때문.
  • 정한 방식: 대화창 Claude는 요구 사항 문서(_drafts/REQ_…md)를 쓰고, Code 탭 Claude는 그 문서대로 고친 뒤 보고서(REPORT_…md)를 남긴다. 사람은 두 문서를 오가며 결정과 승인만 한다.
  • 알아 두면 좋은 말 Code 탭은 Claude 데스크톱 앱 안의 코딩용 작업 공간. 폴더를 열어 파일을 직접 고치고 명령을 실행한다.

4:45번역 원칙 정하기

  • 컴퓨터 용어(File, Folder, USB)는 영어 그대로, 화면 버튼 이름은 "한국어 + 영어"로. 학생이 실제 한국 컴퓨터 화면에서 찾을 수 있게.

6:15다음 학기까지 쓸 수 있게

  • 검사와 변환을 한 번 쓰고 버릴 작업이 아니라 프로그램으로 남기기로 함. 오늘 밤은 1주차만.

7:15Code 탭의 1단계 작업

  • AI가 한 일 고치기 전 상태를 Git에 기록하고, 19개 페이지 화면을 찍어 둠. 고친 뒤 전후 비교 화면을 만들어 바뀐 곳을 스스로 확인. 보고서를 쓰고 내 컴퓨터에만 저장.
  • 알아 두면 좋은 말
    • Git 기록(커밋): 파일의 그때 상태를 저장해 두는 것. 문제가 생기면 이 시점으로 되돌릴 수 있다.
    • 전후 비교 화면: 고치기 전·후 화면을 나란히 찍어 의도하지 않은 변화가 없는지 보는 방법. 사람이 하면 페이지마다 눈으로 비교해야 하는 일.

9:30보고서 검토와 수정 요청서

  • 대화창 Claude가 보고서를 읽고 "내일 수업 전에 꼭 고칠 것"만 추림 → 수정 요청서(REQ_fix-01.md)로 만들어 Code 탭에 넘김.
  • 11:15 Code 탭은 쪽 번호 규칙(1/18 형식)과 휴대폰 화면에서 표가 넘치는 문제를 고침.

12:30오른쪽 Shift 문제 진단

  • 내가 한 일 타자 연습 앱에서 오른쪽 Shift가 왼쪽처럼 처리되는 화면을 캡처해 보냄.
  • AI가 한 일 키보드가 보내는 신호를 그대로 보여 주는 진단 화면을 붙이고, 내가 직접 눌러 보게 함. 메모장에서도 확인하게 해서 원인이 프로그램이 아니라 이 컴퓨터의 키보드 설정이라는 것을 찾아냄. 확인 후 앱은 원래 상태로 되돌림.
  • 핵심 짐작으로 코드를 고치지 않고, 원인을 확인한 뒤 고칠 필요가 없으면 되돌렸다.

14:30짧은 주소 만들기

  • 학생이 치기 쉽게 강의 사이트와 타자 연습 프로그램의 짧은 주소(is.gd)를 만들고 첫 화면에 바로 가기 버튼을 넣음.

19:45공개 전 점검표 (이 편의 핵심 장면 ②)

  • AI가 한 일 올라갈 파일 목록, 개인 정보(이메일·전화번호·학생 실명) 검사 결과, 공개에서 빠지는 초안 폴더(_drafts/)를 표로 보여 주고 승인을 기다림.
  • 내가 한 일 점검표를 보고 승인 → Code 탭이 Github에 올리고 공개 사이트에서 확인.
  • 핵심 AI가 공개 직전까지 다 준비해도, 올리는 결정은 사람이 한다.

21:15화면 배치 다듬기

  • 1교시 카드를 위아래로 쌓아 휴대폰에서도 읽기 쉽게 바꿈.

22:15장면 메모와 설명 원고 틀

  • 장면마다 메모(펼치기 제목, 요약)와 원고(자세히 읽어 보기)를 넣는 틀을 정함. 내가 장면별 글을 주면 Code 탭이 그대로 넣는다.

25:15순위표 정리와 닉네임 겹침

  • 내 요구 시험용 이름을 순위표에서 지우고, 같은 닉네임을 막을 수 있는지 물음.
  • AI의 답 Firebase의 보안 규칙으로 같은 닉네임 등록을 막을 수 있음. 이메일 일부를 보여 주는 것보다 계정 번호 끝 4자리로 구분하는 편이 개인 정보에 안전하다고 권함.

27:00원고는 누가 쓰나

  • 장면 원고를 Code 탭에 바로 줘도 되는지 묻고, "대화창에서 원고 쓰기 → Code 탭에서 넣기"로 역할을 다시 확인.

30:00Notion 기록을 읽고 원고 쓰기

  • AI가 한 일 Notion에 정리해 둔 관광대 강의 기록을 읽고 장면별 메모·원고 형식을 정함.
  • 31:45 1교시 하드웨어 장면 원고를 함께 씀. "웨어하우스"가 학생에게 어떻게 들릴지 묻자, 사전과 기사를 찾아 ware(물건)의 뜻을 확인하고 외우기 쉬운 설명으로 바꿈.

35:00자세히 읽어 보기 화면

  • 원고를 넘기면 Code 탭이 페이지마다 장면을 펼쳐 읽는 화면을 만듦. 브라우저 번역으로 미얀마어에서도 읽히는지 확인.

38:30사진과 출처 넣기

  • AI가 한 일 무료 이미지 사이트(Pixabay 등)에서 메인보드·마우스 사진을 받아 자르고, 사진마다 출처를 적음. USB 화면 캡처에 개인 폴더 이름이 보인다고 공개 전에 먼저 경고.
  • 40:45 공개 사이트에서 메인보드, 마우스, USB 장면을 열어 확인.

42:15한글 2020 글쇠 장면과 마무리

  • 같은 방식으로 한글 수업 장면을 바꾸고 공개 전 점검표를 받아 마무리.
