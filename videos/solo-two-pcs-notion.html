Claude 탭은 머리, Code 탭은 손발?[노션 한 장으로 노트북·PC 잇기]

컴퓨터 이사, 에이전트 팀, 방식 비교처럼 AI와 일하는 방법을 실험합니다.

내 요구AI가 한 일알아 두면 좋은 말핵심

⚠ 영상을 열면 먼저 화질을 1080p로 바꿔 주세요

화면을 녹화한 영상이라 YouTube가 자동으로 고르는 화질(720p 이하)에서는 글씨가 뭉개져 읽을 수 없습니다. 1080p로 바꾸면 글씨가 또렷하게 보입니다.

화질 바꾸는 방법 (눌러서 보기)
  1. 컴퓨터: 영상을 재생하고 화면 오른쪽 아래 ⚙ 설정 → 화질 → 1080p HD를 누릅니다. 화질 옆에 "자동 (720p)"처럼 보이면 아직 바꾸지 않은 것입니다.
  2. 휴대폰 YouTube 앱: 영상 화면을 한 번 누르고 위쪽 ⚙ → 화질 → 고급 → 1080p를 고릅니다.
  3. 가능하면 전체 화면으로 보세요. 작은 창에서는 글씨가 더 작아집니다.

Claude 탭은 머리, Code 탭은 손발?

[노션 한 장으로 노트북·PC 잇기]

28:01▶ 영상 보기

Claude 데스크톱 앱의 Claude 탭은 내가 연결한 폴더를 들여다볼 뿐 PC에서 명령을 실행하지 못하고, Code 탭은 내 PC 안에서 읽고·쓰고·실행까지 합니다. 노트북과 PC의 폴더를 맞추면서, 컴퓨터마다 Claude 탭과 Code 탭, 모두 네 Claude를 노션 "소통 게시판" 한 장으로 잇습니다. 처음에는 Claude 탭이 기획(머리)을, Code 탭이 실행(손발)을 맡았지만, 노션이 전달을 맡자 Claude 탭이 할 일이 없어지는 반전도 함께 보여 줍니다.

이 영상으로 전하고 싶은 것

Claude 데스크톱 앱에는 Claude 탭과 Code 탭이 있습니다. 같은 앱, 같은 Claude처럼 보이지만 일하는 곳과 손발이 다릅니다. 이 차이를 모르면 "왜 이건 되고 저건 안 되지?"에서 막힙니다. 이 영상은 노트북과 데스크톱의 작업 폴더를 맞추는 실제 일을 하면서 그 차이를 하나씩 확인한 기록입니다.

1. 두 탭은 일하는 곳이 다르다

할 수 있는 일Claude 탭Code 탭
일하는 곳클라우드(인터넷 너머 서버)내 PC 안
웹 검색, 노션 읽고 쓰기가능가능
내 PC 폴더대화를 시작할 때 연결한 폴더만, 들여다보고 가져오기허락한 범위 안의 모든 폴더를 읽고 쓰기
명령 실행(git clone, 복사, 서버 켜기)불가. PC에서 명령을 실행하는 도구가 없음가능
PC 안 서버(127.0.0.1) 열어 보기불가가능(앱 안 브라우저로 화면 확인까지)

한 줄로 줄이면, Claude 탭의 손발은 클라우드에는 있고 내 PC에는 없습니다. Code 탭은 내 PC 안에서 돌기 때문에 PC의 명령 창·파일·내부 주소가 모두 보입니다. 그래서 이 영상에서 저장소 내려받기, 서버 켜고 화면 확인, USB 복사와 개수·크기 검증은 모두 Code 탭이 했습니다.

이름도 이렇게 가릅니다. 앱은 건물, 탭은 방입니다. Claude 탭에서 일하면 Claude, Code 탭에서 일하면 Claude Code입니다. "어느 앱인가"가 아니라 "어느 방에서 어떤 손발로 일하는가"가 이름을 정합니다.

2. 대화는 공유되지만, 폴더 권한은 따라오지 않는다

Claude 탭의 대화는 클라우드에 있습니다. 그래서 노트북과 데스크톱에서 같은 계정으로 로그인하면 같은 대화창이 양쪽에 보이고, 이어서 이야기할 수 있습니다.

그런데 폴더 권한은 그 대화를 시작한 컴퓨터에서 받은 것입니다. 노트북에서 시작한 대화는 데스크톱에서 열어도 노트북 폴더만 볼 수 있고, 대화 안에서 폴더를 바꿀 수도 없었습니다. 데스크톱 폴더를 보려면 데스크톱 앱에서 새 대화를 열고 폴더를 다시 연결해야 합니다.

새 대화가 생기면, 같은 계정이라도 두 대화는 서로의 내용을 모릅니다. 그래서 두 대화가 서로 이야기할 길을 따로 만들어야 합니다.

3. 같은 컴퓨터 안의 두 탭도 서로 말하지 못한다

한 컴퓨터 안에서도 Claude 탭과 Code 탭은 직접 대화할 수 없습니다. 결국 이 영상에는 노트북의 Claude 탭·Code 탭, 데스크톱의 Claude 탭·Code 탭, 모두 네 Claude가 있고, 그중 누구도 서로 직접 말하지 못합니다.

4. 해결: 노션 페이지 한 장을 공용 게시판으로

노션 페이지 하나를 "소통 게시판"으로 정하고, 모든 메시지를 표의 한 줄로 남겼습니다. 아파트 게시판에 쪽지를 붙이면 이웃이 와서 읽고 답을 붙이는 방식과 같습니다.

  • 한 줄 형식: 번호(M1, M2…) / 보내는 이 → 받는 이 / 종류(요청·결과·질문·결정 요청) / 내용 / 상태(대기·진행·완료).
  • 에이전트는 스스로 깨어나지 않습니다. 사람이 해당 창에 "게시판 읽고 나에게 온 대기 메시지 처리해"라고 한 줄만 보내면, 읽고 일하고 결과를 게시판에 적습니다.
  • 비밀 값(.env, API 키, 토큰)은 게시판에 적지 않고 "있음/없음"만 적습니다. 값은 사람이 직접 옮깁니다.

한 바퀴는 이렇게 돕니다.

  • ① 노트북 Claude 탭이 게시판에 "데스크톱 Code: 폴더 열두 개 상태를 조사해 표로 적어 줘"라고 씁니다.
  • ② 나는 데스크톱 Code 탭에 "게시판 읽고 처리해"라고 보냅니다.
  • ③ 데스크톱 Code 탭이 실제로 조사하고, 결과 표를 게시판에 적습니다.
  • ④ 노트북 Claude 탭이 그 표를 노트북 결과와 비교해 "내려받을 것, 맞출 것" 목록과 다음 요청을 씁니다.

5. 반전: Claude 탭이 할 일이 없어졌다

처음 계획은 Claude 탭이 머리(기획, 다른 컴퓨터 상황 전달), Code 탭이 손발(지시를 받아 내 PC에서 실행)이었습니다. 그런데 노션 게시판이 전달을 맡자, 계획을 세우고 결과를 비교하는 일도 Code 탭이 게시판을 읽고 쓰면서 할 수 있게 되었습니다. 데스크톱 Claude 탭은 "검토 역할로 쓸 수 있다" 정도만 남았습니다.

여기서 배운 것은 이렇습니다. 에이전트끼리 같은 기록을 볼 수 있으면, 중간에서 말을 옮겨 주는 역할은 필요 없어집니다. 머리와 손발을 나누는 것보다, 모두가 같은 게시판을 보게 하는 것이 먼저입니다.

6. 사람이 쥔 것은 로그인·승인·범위

  • 로그인과 비밀번호 입력은 사람이 직접 합니다. 에이전트는 비밀번호를 넣지 않습니다.
  • "지금 내려받기부터 하자"는 계획이 나왔지만, 먼저 화면 테스트로 충분한지 보자고 사람이 멈추고 그 요청을 취소했습니다.
  • 옮길 목록이 기계적으로 넓어졌을 때, 사람이 "이 폴더는 무슨 용도인가"를 물어 필요 없는 폴더를 뺐습니다.
  • 작업이 길어지자 "30분 안에 끝낼 수 있는 것만"으로 범위를 줄이고, 오래 걸리는 공개 배포는 강연 뒤로 미뤘습니다.

여러분도 컴퓨터가 두 대이거나, 대화창 AI와 코딩 에이전트를 함께 쓴다면 같은 방법을 쓸 수 있습니다. 공용 페이지 한 장, 한 줄 형식, "게시판 읽고 처리해" 한 마디면 됩니다.
