⚠ 영상을 열면 먼저 화질을 1080p로 바꿔 주세요

화면을 녹화한 영상이라 YouTube가 자동으로 고르는 화질(720p 이하)에서는 글씨가 뭉개져 읽을 수 없습니다. 1080p로 바꾸면 글씨가 또렷하게 보입니다.

화질 바꾸는 방법 (눌러서 보기)
  1. 컴퓨터: 영상을 재생하고 화면 오른쪽 아래 ⚙ 설정 → 화질 → 1080p HD를 누릅니다. 화질 옆에 "자동 (720p)"처럼 보이면 아직 바꾸지 않은 것입니다.
  2. 휴대폰 YouTube 앱: 영상 화면을 한 번 누르고 위쪽 ⚙ → 화질 → 고급 → 1080p를 고릅니다.
  3. 가능하면 전체 화면으로 보세요. 작은 창에서는 글씨가 더 작아집니다.

19:42▶ 영상 보기

바이브 코딩으로 한글타자연습앱을 만드는 세 편 중 마지막. 앞의 두 편에서 쓴 첫 요구 사항을 OpenAI의 Codex 데스크톱 앱에 넣고, 빈 폴더에서 시작해 앱 만들기, Shift 문제 진단, Google 로그인과 순위표, Github Pages 배포까지 진행한다.

이 편의 출발점

  • 출발점: 앞의 두 편에서 쓴 첫 요구 사항을 ChatGPT로 정리한 시작 프롬프트(요구사항.md)와 빈 폴더.
  • 일한 곳: 내 컴퓨터의 폴더. OpenAI의 Codex 데스크톱 앱이 파일을 만들고 명령을 실행한다.
  • 이 편의 특징: 오른쪽 Shift 문제를 키보드 신호 진단 페이지를 만들어 풀었고, Firebase 설정 화면 조작과 Github 배포까지 Codex가 직접 했다. 사람은 허용 버튼과 로그인만 했다.

장면별 자세한 설명

0:00소개

  • 완성된 앱 화면 위에 제목이 나오고, 이 편에서 무엇을 하는지 먼저 설명한다.

0:22ChatGPT로 시작 프롬프트 만들기

  • 내 요구 Codex가 사람 도움 없이 기획부터 완성까지 할 수 있는지 보려고, 앞의 두 편에서 쓴 첫 요구 사항을 ChatGPT에게 시작 프롬프트로 정리하게 함.
  • 알아 두면 좋은 말 Codex 데스크톱 앱은 OpenAI가 만든 코딩 AI 프로그램. 내 컴퓨터의 폴더를 열어 파일을 만들고 명령을 실행한다.

0:58빈 폴더에서 계획 세우기

  • AI가 한 일 폴더가 비어 있는지 확인하고, 화면 구성·연습 방식·기록 저장·파일 구조를 담은 개발 계획을 먼저 보여 줌.
  • 내가 한 일 배경 음악 MP3 4곡을 폴더에 넣고 "구현해도 된다"고 승인.

1:34첫 구현과 빈 화면

  • AI가 한 일 파일을 만들고 자동 테스트까지 통과시킴. 단, 브라우저로 화면을 직접 확인하는 단계는 막혀서 하지 못함.
  • 내 요구 열어 보니 화면이 비어 있어 캡처를 보내고 고쳐 달라고 함 → 원인을 찾아 고치자 연습 화면과 키보드가 나옴.
  • 알아 두면 좋은 말 자동 테스트는 AI가 짠 작은 확인 프로그램. 계산이 맞는지는 보지만, 화면이 제대로 보이는지는 사람이 열어 봐야 알 때가 많다.

3:22화면 다듬기와 기록 확인

  • 내 요구 한 화면 안에 다 들어오게, 입력 기록 칸 위치와 줄 수를 바꾸게 함. 미얀마어로 바꿔 보고 TXT 기록 다운로드도 확인.

5:10오른쪽 Shift가 오답이 되는 문제 (이 편의 핵심 장면 ①)

  • 증상 쌍자음 연습에서 오른쪽 Shift로 바르게 쳐도 오답 처리.
  • AI가 한 일 짐작으로 고치지 않고, 키보드가 보내는 신호를 그대로 보여 주는 진단 페이지를 따로 만듦. 확인해 보니 이 컴퓨터는 오른쪽 Shift를 구분하는 신호를 보내지 않았음. 그래서 사용자가 자기 키보드에 맞춰 Shift를 정해 두는 Shift 설정 기능을 붙임.
  • 왜 대단한가 사람이 하면 개발자 도구를 열어 키 이벤트를 하나씩 찍어 봐야 하는 일. AI가 확인 도구까지 스스로 만들어 원인을 좁혔다.

8:22Firebase로 Google 로그인 붙이기

  • AI가 한 일 브라우저를 열어 Firebase 설정 화면을 찾아가 로그인 방식에 Google을 켜고, 로그인할 수 있는 주소를 등록함. 내 컴퓨터에 시험용 서버도 띄움.
  • 내가 한 일 AI가 브라우저를 조작해도 되는지 묻는 창에서 허용, Google 계정으로 로그인.
  • 알아 두면 좋은 말
    • Firebase: Google의 앱 뒷단 서비스. 서버 없이 로그인과 데이터 저장을 쓸 수 있음.
    • Authentication: "누가 들어왔는지" 확인하는 로그인 장치.
    • 시험용 서버(localhost): 내 컴퓨터 안에서만 열리는 임시 웹 주소. Google 로그인은 파일을 바로 열면 막히고 이런 주소에서만 된다.

10:52강연용으로 쉽게 설명받기

  • 내 요구 로그인을 왜 만들었고 Firebase가 무엇인지 청중이 알아듣게 설명해 달라고 함. 설명을 강의 자료 파일(LECTURE_LOGIN_GUIDE.md)로 받아 저장.
  • AI의 비유 로그인은 도서관 출입증처럼 학생을 구분하고, 기록을 그 학생 칸에 안전하게 쌓는 방법.

12:10순위표, 닉네임, 관리자 화면

  • 내 요구 학생별 누적 기록, 순위표, 닉네임, 관리자 전용 화면을 한 번에 요청. Codex가 점수 방식을 묻자 "정답 1점, 오타 1점 감점, 최소 0점"으로 정함.
  • AI가 한 일 몇 분 동안 혼자 12개 파일을 고치고 시험함. 학생 기록을 Firestore에 쌓고, 학생은 자기 기록만, 관리자는 전체를 보게 규칙을 만듦.
  • 알아 두면 좋은 말 Firestore는 학생 기록을 모아 두는 인터넷 저장소. 어느 컴퓨터에서 접속해도 같은 기록이 보인다.

14:00로그인 버튼이 안 눌리는 문제

  • 원인 파일을 바로 연 화면이었음. 시험용 서버 주소로 열자 로그인, 순위표, 관리자 모드가 나옴.

15:36Shift 설정이 다시 안 될 때 (이 편의 핵심 장면 ②)

  • 내 요구 "왜 안 되지? 이전에 성공한 코드와 비교해서 고쳐 줘."
  • AI가 한 일 파일로 열 때와 서버 주소로 열 때 설정이 따로 저장된다는 원인을 찾고, 같은 설정을 쓰게 고침. 자동 테스트도 다시 통과.

17:12Github에 올리고 배포하기

  • 내 요구 커밋·푸시하고 배포까지 마무리. 음악 4곡도 함께 올리기로 함.
  • AI가 한 일 Github 저장소에 올리고 Github Pages 배포까지 진행. 저장소에 파일이 안 보인다는 질문에는 올라간 위치를 확인해 주고, 메일로 온 보안 경고는 Firebase 설정값 때문이라고 설명. "Google로 배포한 거냐"는 되물음에는 사이트는 Github Pages, Google(Firebase)은 로그인과 기록 저장에만 쓴다고 정리.
  • 알아 두면 좋은 말 Github Pages는 Github 저장소의 파일을 그대로 웹사이트로 열어 주는 무료 서비스.

18:48배포된 사이트에서 연습해 보기

  • 실제 주소에서 로그인, 쌍자음 연습, 관리자 모드, 기록 다운로드까지 확인.
