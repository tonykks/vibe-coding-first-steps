⚠ 영상을 열면 먼저 화질을 1080p로 바꿔 주세요

화면을 녹화한 영상이라 YouTube가 자동으로 고르는 화질(720p 이하)에서는 글씨가 뭉개져 읽을 수 없습니다. 1080p로 바꾸면 글씨가 또렷하게 보입니다.

화질 바꾸는 방법 (눌러서 보기)
  1. 컴퓨터: 영상을 재생하고 화면 오른쪽 아래 ⚙ 설정 → 화질 → 1080p HD를 누릅니다. 화질 옆에 "자동 (720p)"처럼 보이면 아직 바꾸지 않은 것입니다.
  2. 휴대폰 YouTube 앱: 영상 화면을 한 번 누르고 위쪽 ⚙ → 화질 → 고급 → 1080p를 고릅니다.
  3. 가능하면 전체 화면으로 보세요. 작은 창에서는 글씨가 더 작아집니다.

① AI Studio

29:33▶ 영상 보기

바이브 코딩으로 한글타자연습앱을 만드는 세 편 중 첫 번째. Google AI Studio의 Build 모드에 요구 사항 파일 하나를 주고, 앱 만들기부터 Google 로그인·순위표·Github Pages 배포까지 진행한다. AI가 어디까지 해 주고 어디서 사람이 나서야 하는지가 잘 보인다.

이 편의 출발점

  • 출발점: 미리 써 둔 요구 사항 파일(Build-Mode_요구사항.md) 하나와 배경 음악 MP3 4곡.
  • 일한 곳: 설치 없이 브라우저 안에서 쓰는 Google AI Studio의 Build 모드.
  • 이 편의 특징: Firebase 로그인과 데이터베이스 연결은 AI Studio가 스스로 했고, Github에 저장소를 만들고 올리는 일은 보안 때문에 사람이 버튼을 눌러 했다.

한눈에 보는 역할 나누기

단계내가 한 일AI(Gemini)가 한 일
앱 만들기요구 사항 파일과 MP3 음악 올리기계획 세우기, 수십 개 파일 나눠 만들기, 미리보기 실행
고치기써 보고 문제 화면을 캡처해 알려 주기원인 찾기, 코드 고치기, 확인용 장치 넣기
로그인·기록요청문 다듬기, Google 계정으로 로그인 허락Firebase 프로젝트 만들기, 로그인·데이터베이스·보안 규칙 연결
배포Github 비밀번호 확인, 저장소 정리, Pages 설정, Firebase에 주소 등록자동 배포 설정 파일 만들기, 할 일 순서 안내
장면별 자세한 설명

0:00소개

  • 완성된 앱 화면 위에 제목이 나오고, 이 편에서 무엇을 하는지 먼저 설명한다.

0:29요구 사항 파일 하나로 시작

  • 내 요구 미리 써 둔 Build-Mode_요구사항.md를 올리고 앱을 만들어 달라고 함. 배경 음악 MP3 4곡을 올림.
  • AI가 한 일 요구 사항을 읽고 계획을 세운 뒤, 화면·가상 키보드·연습 세트·3개 언어 번역·음악 재생·TXT 저장을 각각 다른 파일로 나눠 만듦. 몇 분 만에 미리보기에서 바로 연습 가능.
  • 알아 두면 좋은 말 Build 모드는 설치 없이 브라우저 안에서 코드를 만들고 바로 실행해 보는 Google AI Studio 기능.

2:53직접 써 보기

  • 연습 세트를 골라 쳐 보고, 연습을 마치면 결과를 TXT로 저장하는 창까지 확인.

4:05Shift 쌍자음 문제 고치기

  • 내 요구 9세트 Shift 연습이 안 되는 화면을 캡처해 알려 줌.
  • AI가 한 일 키 입력을 실시간으로 보여 주는 확인 장치를 넣고 Shift 판정 방식을 고침.

6:05언어 바꾸기와 Space 글쇠

  • 내 요구 미얀마어·베트남어로 바꿔 보다가 Space 글쇠 안의 글자를 지워 달라고 하고, 왜 넣었는지 물음.

7:17다음 단계 요청문을 Gemini 채팅에서 다듬기

  • 내 요구 Google 로그인, 학생별 기록 저장, 순위표, 관리자 화면을 정리한 요청문을 따로 Gemini에게 다듬게 함.

8:17Firebase 자동 연결 (이 편의 핵심 장면)

  • AI가 한 일 요청문을 붙여 넣자 AI Studio가 Firebase 프로젝트를 직접 만들고, 데이터 구조 설계도(firebase-blueprint.json), 보안 규칙(firestore.rules), 로그인·순위표·관리자 화면 파일을 만듦.
  • 알아 두면 좋은 말
    • Firebase: Google의 앱 뒷단 서비스. 서버를 직접 만들지 않아도 로그인과 데이터 저장을 쓸 수 있음.
    • Authentication: "누가 들어왔는지" 확인하는 로그인 장치. 여기서는 Google 계정으로 로그인.
    • Firestore: 학생별 연습 기록을 모아 두는 인터넷 저장소. 어느 컴퓨터에서 접속해도 같은 기록이 보임.
    • 보안 규칙: 학생은 자기 기록만, 관리자는 전체 기록을 보게 막는 약속.
  • 왜 대단한가 사람이 하면 Firebase 사이트에서 프로젝트를 만들고, 로그인 방식을 켜고, 설정값을 코드에 옮기고, 보안 규칙을 따로 써야 하는 일. 여기서는 내가 한 일이 Google 로그인 허락 하나뿐이다.

9:41로그인해 보고 요구 덧붙이기

  • 내 요구 로그인해 보고 "관리자 계정은 순위에서 빼 줘", "Shift 호환 버튼은 무슨 기능이야?"처럼 써 보면서 생긴 요구를 덧붙임. 다른 계정으로도 로그인해 학생 화면을 확인.
  • AI가 한 일 순위표 Top 5, 닉네임 정하기, 관리자 전용 화면, 화면 흔들림 수정.

13:17순위표에서 학생 기록 보기

  • 내 요구 순위에서 학생을 누르면 지금까지의 기록(연습 시간, 점수, 오타 수)이 모두 보이게 해 달라고 함.
  • AI가 한 일 학생별 상세 기록 창을 만듦.

14:29Github 계정 연결

  • 내가 한 일 AI Studio에 Github를 연결하면서 비밀번호 확인과 저장소 선택을 직접 함. AI가 대신할 수 없는 단계.
  • 14:53 "로그인은 왜 있는 거지요?"에 대한 답: 기록을 학생마다 구분하고 안전하게 쌓기 위해서.

15:41코드를 내 컴퓨터로 받기

  • 내 요구 전체 코드를 zip으로 받는 방법을 물음.
  • AI가 한 일 다운로드 버튼을 달고, 내 컴퓨터에서 실행하는 명령(npm install, npm run dev)을 알려 줌. 학생 화면에는 필요 없어 버튼은 다시 지움.

17:29고치다 생긴 문제는 되돌리기

  • 내 요구 흔들림이 다시 생기자 "zip 파일 만들기 전으로 되돌려 주세요"라고 요청. 미얀마어에서만 흔들리는 문제도 짚음.
  • 알아 두면 좋은 말 AI Studio는 단계마다 저장 지점(Checkpoint)이 있어서 이전 상태로 되돌릴 수 있음.

19:53Github에 배포하기

  • 내 요구 Github에 build_hangul-key 저장소를 만들고 올려서 배포해 달라고 함.
  • AI가 한 일 Github Pages에 자동 배포하는 설정 파일(.github/workflows/deploy.yml)을 만듦. 그러나 저장소를 만들고 올리는 일은 직접 하지 못함.

22:53AI는 왜 직접 올리지 못하나 (AI가 어디까지 하는지 보여 주는 장면)

  • 내 요구 "왜 저장소도 못 만들고 push도 못 하지?"
  • AI의 답 보안 때문. AI가 내 Github 계정 열쇠(토큰)를 들고 마음대로 저장·배포하지 못하게 막혀 있고, 마지막 결정은 사람이 하도록(Human-in-the-loop) 되어 있음.
  • 정리 AI Studio는 코드를 만들고 고치는 데까지, 계정 권한이 필요한 일은 사람이 버튼을 누르거나 직접 해야 함.

25:05Github 연결 버튼으로 올리기

  • 내가 한 일 같은 이름의 빈 저장소가 이미 있어서 Github에서 직접 지움. AI Studio의 Github 버튼으로 새 저장소를 만들고 코드를 올림. Github Pages 설정을 Github Actions로 바꿈.
  • AI가 한 일 순서를 안내하고, 올린 코드를 Github가 자동으로 빌드·배포하게 설정해 둠.

27:17배포 사이트에서 로그인이 안 될 때

  • 원인 Firebase는 허락한 주소에서만 로그인을 받음. 새 주소(…github.io)를 Firebase의 승인된 도메인에 넣어야 함.
  • 내가 한 일 Gemini 채팅에서 방법을 묻고, Firebase 콘솔에 직접 주소를 등록. 등록 후 배포 사이트에서도 로그인과 기록 보기가 됨.

28:33마무리: 음악 경로 고치기

  • 내 요구 배포 사이트에서 음악이 안 나오는 문제 등 세 가지를 고쳐 달라고 함.
  • AI가 한 일 배포 주소에 맞게 음악 파일 경로를 고치고 오류 안내를 넣음. Github 버튼으로 다시 반영.
