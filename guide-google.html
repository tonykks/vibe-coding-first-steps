GOOGLE 유료 구독자 및 AI STUDIO 사용자용 사용 설명서

바이브코딩에서 나만의 AI Agent까지 — Google 생태계 편

Google의 바이브코딩 환경은 단순한 대화형 챗봇에 머물지 않고 기획(Gemini) → 웹 프로토타이핑 및 풀스택 빌더(AI Studio) → 로컬 정밀 개발(Antigravity IDE) → 실제 서비스 운영 인프라(Firebase · Google Cloud)가 하나로 이어진 종합 생태계입니다.

STEP 1 · 기획 및 설계

Gemini 웹앱 (gemini.google.com)

  • 대화를 통해 해결할 문제와 요구사항 정의
  • Canvas 기능으로 문서·단일 웹 코드 즉시 확인
  • 구글 워크스페이스(Docs, Drive) 연동 작업
STEP 2 · 웹 실험 및 올인원 빌더

Google AI Studio (Playground / Build)

  • Playground: 프롬프트 실험 및 단일 HTML 생성
  • Build Mode: 다중 파일 풀스택 앱 자율 제작
  • Firebase 연동 및 원클릭 클라우드 배포(Publish)
STEP 3 · 로컬 및 원격 정밀 개발

Antigravity IDE (데스크톱 앱)

  • 내 PC 폴더에 음악(MP3)·이미지를 넣으면 즉시 인식
  • 수정할 줄만 정밀하게 고치는 차분 패치(Diff)
  • 작업 즉시 내 컴퓨터 하드디스크에 영구 자동 보관
STEP 4 · 백엔드 및 글로벌 배포

Firebase & Google Cloud

  • Authentication: 구글 계정 로그인 관리
  • Firestore DB: 사용자별 데이터·랭킹 영구 저장
  • Cloud Run: 전 세계 어디서나 접속하는 웹 주소
이 매뉴얼의 활용법: 강연 중에는 왼쪽 목차를 따라가며 각 도구의 역할과 차이를 눈으로 확인하고, 귀가 후 혼자 실습할 때는 G07~G09의 단계별 절차와 프롬프트를 그대로 복사해 참고서로 활용하세요.
G01

Google 바이브코딩 서비스 지도

접근 방법(Web/Desktop)과 실제 작업이 실행되는 장소(Cloud/Local)를 구분하면 전체 구조가 한눈에 보입니다.

G01-01. 네 가지 핵심 작업 공간의 역할

서비스 명칭 접속 경로 핵심 역할 한 줄 정의 바이브코딩 입문 적합도
Gemini 웹앱 웹 브라우저 (gemini.google.com) 아이디어 구체화, 요구사항 명세서 작성, 단일 코드 생성 매우 적합 (기획 단계)
AI Studio · Playground 웹 브라우저 (aistudio.google.com) 모델 설정을 조절하며 프롬프트 반응과 단일 HTML을 실험하는 실험실 매우 적합 (단일 파일 검증)
AI Studio · Build Mode 웹 브라우저 (aistudio.google.com) 여러 파일로 구성된 웹앱을 스스로 설계·구현·배포하는 웹 공방 핵심 입문 도구 (설치 불필요)
Antigravity IDE 데스크톱 앱 설치 (Windows/macOS/Linux) 내 PC의 폴더와 파일을 직접 읽고 정밀하게 수정하는 전문 작업실 필수 확장 도구 (지속 개발용)

G01-02. 접근 방법(Web / Desktop)과 작업 장소(Cloud / Local) 구분

어디로 접속하는가? (접근 방법)
  • Web (웹 브라우저): 별도 프로그램 설치 없이 인터넷 주소로 접속 (Gemini, AI Studio)
  • Desktop (데스크톱 앱): 내 컴퓨터에 프로그램을 설치하여 실행 (Antigravity IDE)
어느 컴퓨터에서 작업하는가? (작업 장소)
  • Cloud (클라우드): Google의 원격 가상 컴퓨터에서 파일 생성·빌드 수행
  • Local (로컬): 내 컴퓨터의 하드디스크 폴더에서 직접 파일 읽기·쓰기·실행
G02

웹 브라우저에서 할 수 있는 것 (Gemini & AI Studio)

내 컴퓨터에 아무것도 설치하지 않고 브라우저 탭 하나로 기획부터 배포까지 수행하는 방법입니다.

G02-01. Gemini 웹앱 (대화 · 기획 · Canvas)

주요 기능과 활용

  • 요구사항 구체화 (Vibe Agent 역할): 만들고 싶은 프로그램의 대상, 핵심 기능, 제외할 기능, 검수 기준을 대화로 정리하여 요구사항.md 문서로 만듭니다.
  • Canvas (캔버스): 대화창 우측에 별도 작업 창을 열어 문서나 HTML/React 단일 페이지 코드를 즉시 수정하고 미리보기로 실행합니다.
  • 한계: 내 PC의 로컬 폴더를 직접 읽거나 여러 파일로 나뉜 대규모 프로젝트 구조를 관리하고 GitHub에 직접 Push하는 기능은 제공하지 않습니다.

G02-02. AI Studio : Playground vs Build Mode 비교

Google AI Studio 안에는 성격이 전혀 다른 두 가지 작업 모드가 존재합니다.

구분 기준 Playground (아이디어 실험실) Build Mode (올인원 자율 개발 공방)
작업 형태 단일 질의응답 및 모델 파라미터(온도 등) 실험 프로젝트 단위 자율 개발 (Coding Agent 방식)
결과물 코드 구조 하나의 HTML 파일 안에 CSS·JS가 모두 합쳐진 단일 파일 src/, public/, 설정 파일 등이 분리된 정식 폴더 구조
백엔드 연동 순수 브라우저 화면 위주 (백엔드 연동 어려움) Firebase(구글 로그인, Firestore DB), 외부 API 연동 공식 지원
코드 반출 (소장) 단일 코드 복사 또는 단일 파일 다운로드 Download as .zip, Push to GitHub, Export to Antigravity
웹 배포 (Publish) 만든 파일을 사용자가 직접 호스팅 서버에 올려야 함 상단 Publish 버튼 클릭 한 번으로 Cloud Run 웹 주소 즉시 생성

G02-03. Build Mode 화면 구성과 주의할 점

1

채팅 입력창과 추천 프롬프트 칩 (Shortcut 버튼) 주의

입력창 위에 나타나는 AI Features나 디자인(Create Application Layout) 박스는 템플릿 버튼입니다. 명확한 요구사항 문서가 있을 때는 이 버튼을 누르지 말고 아래 입력창(Make changes...)에 직접 지시사항을 입력해야 불필요한 기능이 섞이지 않습니다.

2

프리뷰(Preview)와 코드 탐색기(<> / 폴더 아이콘)

화면 우측에서는 AI가 만든 앱이 실시간으로 동작하는 Preview 화면을 조작해 볼 수 있으며, 상단 아이콘을 전환해 생성된 전체 파일 트리(src/, .gitignore, .env.example 등)를 직접 열어볼 수 있습니다.

3

웹 가상 컨테이너의 한계

브라우저 안의 가상 공간에서 작동하므로 대용량 음악(MP3)이나 다수의 이미지 파일을 폴더째 끌어다 놓기 어렵고, 세션이 만료되면 작업 환경이 초기화될 수 있으므로 완성 후 반드시 외부로 백업해야 합니다.

G03

데스크톱 앱에서 할 수 있는 것 (Antigravity IDE)

내 컴퓨터에 설치하여 로컬 폴더의 파일, 터미널, 정밀 코드 수정을 AI 에이전트에게 맡기는 전문 개발 환경입니다.

G03-01. Antigravity IDE 개요와 바이브코딩 방식

비전공자가 Antigravity IDE를 쓴다고 해서 복잡한 개발 명령어를 외워야 하는 것은 아닙니다. Build Mode와 똑같이 에이전트 채팅창에 자연어로 지시하여 작업을 완성합니다. 달라지는 것은 작업 무대가 '구글의 가상 웹 공간'에서 '내 컴퓨터의 실제 폴더'로 바뀐다는 점입니다.

Antigravity IDE의 핵심 강점
  • 직관적인 파일·자산 관리: 윈도우 탐색기나 Mac Finder에서 음악 파일(musics/track.mp3)이나 사진을 프로젝트 폴더에 마우스로 끌어다 놓고 "폴더에 넣은 음악 재생해 줘"라고 말하면 AI가 즉시 인식합니다.
  • 자동 영구 소장: 별도로 다운로드 버튼을 누를 필요 없이, AI가 작성하는 모든 파일이 그 즉시 내 PC 하드디스크에 실물 파일로 저장됩니다.
  • 로컬 CLI 도구 제어: 내 PC에 설치된 Git, Firebase CLI 등을 AI가 직접 실행하여 서버 설정이나 배포 명령까지 대신 수행할 수 있습니다.
사용 시 고려할 한계
  • 초기 환경 준비: 프로그램 설치 및 기본 실행 환경(Node.js, Git 등) 최초 1회 설정이 필요합니다.
  • PC 전원 유지: 로컬 모드로 작업할 때는 내 컴퓨터가 켜져 있고 앱이 열려 있어야 에이전트가 작업을 진행합니다.
  • 배포 단계: 클릭 한 번으로 링크가 나오는 Build Mode와 달리, GitHub Pages나 Vercel 등에 연결하는 배포 절차를 거칩니다.
G04

핵심 원리 비교: 왜 결국 웹 빌더에서 IDE로 넘어가는가?

프로젝트가 커질수록 Build Mode에서 멀쩡하던 기능이 고장 나는 이유와 Antigravity IDE가 이를 해결하는 원리입니다.

G04-01. 코드 수정 메커니즘의 근본적 차이

AI Studio Build Mode : 파일 전체 덮어쓰기 (Full File Rewrite)

수정할 파일의 1번째 줄부터 마지막 줄까지 처음부터 다시 생성하여 덮어씁니다.

  • 오디오 경로 3줄만 고쳐달라고 요청해도 500줄짜리 파일 전체를 새로 출력합니다.
  • 파일이 길어질수록 출력 시간이 오래 걸리고 토큰 소모가 급증합니다.
  • 치명적 부작용: 전체 코드를 다시 쓰는 과정에서 이전에 잘 만들어 두었던 로그인 처리나 타이핑 판정 로직 일부를 AI가 임의로 축약·생략하여 멀쩡하던 기능이 깨지는 현상이 발생합니다.
Antigravity IDE : 차분 패치 (Diff / Patch)

변경이 필요한 몇 줄만 정확히 찾아내어 그 부분만 핀포인트로 교체합니다.

  • 500줄 중 수정이 필요한 42~45번째 줄만 도려내고 새 코드로 바꿉니다.
  • 수정할 부분만 생성하므로 반응 속도가 매우 빠르고 토큰 소모가 적습니다.
  • 완벽한 보존성: 건드리지 않은 나머지 496줄의 기존 기능(구글 로그인, 키보드 검증 등)은 단 한 글자도 바뀔 위험이 없어 100% 안전하게 보존됩니다.

G04-02. 4가지 작업 환경 한눈에 비교하기

비교 항목 Gemini 웹앱 AI Studio : Playground AI Studio : Build Mode Antigravity IDE (로컬)
설치 없이 시작 가능 (브라우저) 가능 (브라우저) 가능 (브라우저) 데스크톱 앱 설치 필요
코드 수정 방식 대화/캔버스 재생성 단일 파일 전체 재생성 파일 전체 덮어쓰기 (Rewrite) 부분 차분 패치 (Diff/Patch)
내 PC 폴더 직접 접근 불가 (개별 파일 첨부) 불가 불가 (웹 가상 컨테이너) 가능 (탐색기 폴더 직결)
음악·이미지 자산 추가 제한적 코드 내 텍스트만 가능 채팅 첨부 제약·경로 주의 폴더에 파일 넣으면 즉시 인식
결과물 내 PC 확보 코드 복사 / 다운로드 단일 HTML 다운로드 ZIP 다운로드 / GitHub / Export 작업 즉시 내 PC에 자동 저장
웹 배포 (Publish) 수동 이관 필요 수동 호스팅 필요 Publish 버튼 원클릭 배포 GitHub Pages / Vercel 등 연동
G05

대화 연결성(Sync)과 클라우드 배포 비용 구조

어디서 작업한 내용이 어디까지 이어지는지, 그리고 무료 한도와 카드 등록의 관계를 명확히 알아둡니다.

G05-01. 서비스 간 대화 및 프로젝트 연결성(Sync)

항목 동기화 및 연결 범위 사용자가 꼭 알아야 할 원칙
Gemini 웹앱 대화 같은 구글 계정의 웹 브라우저 ↔ 모바일 앱 간 동기화 Gemini 웹앱의 일반 대화 목록은 AI Studio와 섞이지 않고 별도로 관리됩니다.
AI Studio 프로젝트 같은 구글 계정 내 AI Studio(웹/모바일 웹)에서 공유 (Google Drive 연동) 단, Build Mode의 가상 실행 컨테이너 상태는 세션 만료 시 초기화될 수 있으므로 GitHub 동기화나 ZIP 백업이 필수입니다.
Build Mode → Antigravity 상단 Export > Export to Antigravity 또는 GitHub로 이관 버튼 한 번으로 프로젝트를 넘길 수 있으며, 지속적인 버전 관리는 GitHub 저장소를 중심축으로 삼습니다.

G05-02. Cloud Run 배포의 '2개 제한'과 카드 결제 등록의 진실

1

카드 미등록 상태: Google Cloud Starter Tier (최대 2개 앱 제한)

결제 수단을 등록하지 않아도 Build Mode의 Publish 버튼으로 앱을 배포할 수 있지만, 무료 스타터 티어는 계정당 최대 2개의 앱(Cloud Run 인스턴스)까지만 허용됩니다. 3번째 앱부터는 배포가 차단됩니다.

2

카드 결제 등록 상태: 표준 배포(Standard Deployment)로 개수 제한 해제

결제 계정(Billing Account)이 연결된 Google Cloud 프로젝트를 선택해 배포하면 '2개 제한'이 즉시 풀리고 필요한 만큼 앱을 배포할 수 있습니다.

3

실제 요금 발생 여부 (무료 할당량)

배포 시 사용되는 Google Cloud Run은 매월 200만 회의 무료 요청(Free Tier)을 기본 제공합니다. 수십~수백 명의 학습자나 지인이 접속해 사용하는 규모는 무료 한도의 극히 일부이므로, 카드를 등록해 두어도 실제 청구 비용은 0원이거나 수십 원 수준으로 유지됩니다.

G06

데이터 처리 모델과 API 키 보안 관리

모델이 생각하는 위치와 코드가 실행되는 위치를 구분하고, 비밀 키 유출로 GitHub 푸시가 막히는 일을 예방합니다.

G06-01. 생각하는 곳(Inference)과 실행하는 곳(Execution)

  • 모델 추론(Inference): Gemini 웹앱, AI Studio, Antigravity IDE 모두 AI 모델의 두뇌 계산은 Google Cloud 서버에서 일어납니다. 데스크톱 앱을 설치한다고 거대 모델이 내 PC에서 직접 도는 것은 아닙니다.
  • 도구 및 파일 실행(Execution): Build Mode는 구글의 클라우드 가상 컨테이너에서 파일을 만들고 실행하며, Antigravity IDE 로컬 작업은 내 컴퓨터(Local)의 폴더와 터미널에서 직접 실행됩니다.

G06-02. API 키 보관과 GitHub 푸시 보호(Push Protection) 해결법

외부 AI 기능(예: OpenAI API, Gemini API 등)을 연동할 때 소스 코드 파일(src/ 내부)에 실제 API 키 문자열을 그대로 적어두면, 비공개(Private) 저장소라도 GitHub의 비밀 검사(Secret Scanning)가 작동하여 푸시를 강제 차단합니다.

비전공자·일반인에게 가장 추천하는 방식 (화면 설정창 입력)

앱 화면 안에 'API 키 설정 입력창'을 만들라고 지시합니다.

  • 프롬프트 지시: "화면 우측 상단에 설정(⚙️) 버튼을 만들고, 사용자가 자신의 API 키를 입력해 브라우저(LocalStorage)에만 저장해서 쓰도록 구현해 줘."
  • 효과: 소스 코드 안에 비밀 키가 전혀 없으므로 GitHub에 바로 올리거나 ZIP으로 배포해도 보안 경고가 절대 뜨지 않습니다.
표준 개발 방식 (Secrets 탭 & .env 분리)

환경 변수와 .gitignore를 활용합니다.

  • Build Mode 상단의 Secrets 탭에 키를 등록하고, 코드에서는 import.meta.env.VITE_API_KEY 형태로만 불러오게 합니다.
  • .gitignore 파일에 .env가 등록되어 있어 GitHub로 푸시할 때 실제 키 파일은 자동으로 제외되고 .env.example 템플릿만 안전하게 올라갑니다.
G07

결과물 보관 장소와 내 PC로 가져오는 3가지 길

'웹에 배포했다'는 것과 '원본 소스 코드를 내 것으로 확보했다'는 것은 전혀 다릅니다.

G07-01. 클라우드 배포(Publish)와 원본 코드 저장(GitHub/ZIP)의 차이

중요 원칙: Google Cloud(Cloud Run)에 Publish(배포)하는 것은 브라우저가 실행할 수 있게 압축된 '최종 실행용 묶음(번들)'만 서버에 띄우는 것입니다. 나중에 코드를 다시 열어 수정하려면 반드시 원본 소스 코드 전체를 GitHub나 내 PC(ZIP)에 별도로 보관해야 합니다.
보관 및 배포 방식 실제로 저장되는 내용 목적 나중에 코드 수정 가능 여부
Playground 다운로드 실행용 단일 HTML 파일 (index.html) 내 PC에서 더블클릭해 즉시 실행·전달 부분 가능 (단일 파일 직접 편집)
Build Mode : Publish (클라우드 배포) 압축·변환된 실행용 컨테이너/번들 학습자·사용자가 접속할 인터넷 주소(URL) 생성 불가능 (실행 전용 상태)
Build Mode : Export (ZIP / GitHub) 원본 소스 코드와 폴더 구조 전체 영구 백업 및 추후 기능 추가·재개발 완벽히 가능 (언제든 수정 가능)

G07-02. Build Mode 상단 [Export] 메뉴의 3가지 반출 경로

Build Mode 우측 상단 메뉴(Publish, Versions, GitHub, Integrations, Secrets 우측의 Export)에서는 다음 세 가지 반출 기능을 공식 제공합니다.

1

Download as .zip file (내 컴퓨터로 원클릭 직접 다운로드)

외부 서비스를 거치지 않고 현재 만들어진 프로젝트 폴더 전체(src/, 설정 파일 등)를 하나의 ZIP 압축 파일로 내 PC 다운로드 폴더에 즉시 내려받습니다. 가장 빠르고 직관적인 백업 방법입니다.

2

Export to Antigravity (Antigravity 환경으로 다이렉트 전송)

Build Mode에서 초안을 완성한 뒤 버튼 한 번을 눌러 Antigravity 워크스페이스로 프로젝트 전체를 그대로 넘겨받아 정밀한 에이전트 작업을 이어갑니다.

3

Push to GitHub (GitHub 저장소 자동 생성 및 동기화)

터미널 명령어(git init 등)를 전혀 몰라도, 계정 연동 후 Create new repository를 누르면 새 저장소를 자동 생성하고 전체 코드를 main 브랜치에 올려줍니다. 최초 보관 시에는 공개 범위를 Private(비공개)으로 선택하는 것이 안전합니다.

G08

혼자 따라 하는 실전 바이브코딩 4단계 절차

집으로 돌아가 혼자 프로젝트를 만들 때 이 순서와 프롬프트를 그대로 복사해 사용하세요.

1단계: 코딩부터 시키지 않고 '기획안 먼저 보고받기'

AI가 요구사항을 잘못 이해한 채 코드를 짜기 시작하면 수정하는 데 더 많은 시간과 토큰이 듭니다. 첫 프롬프트에서는 반드시 코딩을 멈추고 기획안부터 보고하게 지시합니다.

[1단계 복사해서 쓸 프롬프트]
첨부한 요구사항을 주의 깊게 확인해 주세요.
아직 코드를 작성하지 말고 아래 4가지 항목에 대한 기획안을 먼저 보고해 주세요.

1. 요구사항 이해 요약 (핵심 기능과 반드시 제외할 기능 구분)
2. 프로그램 구현 기획안
3. 파일 구성 및 기술 스택 선택 이유
4. 구현 전 승인이 필요한 질문 사항

보고를 확인한 뒤 제가 승인하면 그때 구현을 시작해 주세요.

2단계: 기획안 검토 후 '1차 기본 기능 구현 승인하기'

처음부터 로그인, 데이터베이스, 랭킹을 한꺼번에 시키지 않고 핵심 동작(MVP)부터 완성해 눈으로 검증합니다.

[2단계 복사해서 쓸 프롬프트]
기획안과 질문 사항에 대한 답변을 승인합니다.
제시한 파일 구성에 맞춰 1차 기본 프로그램 구현을 시작해 주세요.
모든 핵심 검수 기준을 충족하도록 작성하고, 완료 후 항목별 자체 검증 결과를 함께 알려주세요.

3단계: 1차 검증 완료 후 '2차 백엔드(Firebase 로그인·DB·랭킹) 확장하기'

1차 화면 동작이 완벽히 확인되면, 기존 로직을 보존하라는 지시와 함께 Firebase 연동을 요청합니다.

[3단계 복사해서 쓸 프롬프트]
1차 개발된 기본 프로그램의 핵심 로직과 화면 구성은 단 한 줄도 누락하지 말고 그대로 유지하면서, 아래의 백엔드 요구사항만 2차 개발로 추가해 주세요.

1. 인증 (Firebase Authentication - Google 계정 전용)
- 구글 계정 로그인만 지원하며, 로그인하지 않은 게스트도 기본 연습 기능을 동일하게 사용할 수 있게 해주세요.
- 최초 로그인 시 별칭(Nickname)을 입력받고, 중복 확인 없이 '별칭(UID끝4자리)' 형태로 상단에 표시해 주세요.

2. 데이터 저장 및 랭킹 (Cloud Firestore)
- 로그인 사용자의 연습 시간을 Firestore에 누적 저장하고, 상위 1~5위 실시간 랭킹을 표시해 주세요.
- 관리자 이메일(ADMIN_EMAIL 상수로 지정)은 랭킹에서 제외하고 전체 학생 기록을 조회하는 관리자 뷰를 제공해 주세요.

4단계: 완성본 안전하게 백업하고 배포하기

마무리 필수 체크리스트

  1. 상단 Export > Download as .zip file을 눌러 내 컴퓨터에 원본 압축본을 먼저 저장합니다.
  2. 상단 GitHub 탭을 클릭해 연동(최초 1회 All repositories 권한 체크 후 Save)하고, Create new repository에서 Private으로 저장소를 생성·동기화합니다.
  3. 즉시 공유가 필요하면 상단 Publish 버튼을 눌러 Cloud Run 웹 링크를 생성합니다.
G09

실전 배포 및 트러블슈팅 매뉴얼

GitHub 배포와 Firebase 연동 과정에서 누구나 한 번씩 겪는 3대 대표 문제의 원인과 해결법입니다.

문제 1. GitHub Actions 배포 시 빨간색 실패(X)가 뜰 때

원인과 해결 절차 (Workflow 쓰기 권한 부여)

GitHub 저장소의 기본 보안 설정이 '읽기 전용'으로 되어 있어 빌드된 웹페이지를 배포 브랜치에 쓰지 못해 발생하는 현상입니다.

  1. 내 GitHub 저장소 상단 탭에서 Settings(톱니바퀴)를 클릭합니다.
  2. 왼쪽 사이드바 중간의 Actions > General 메뉴를 클릭합니다.
  3. 화면을 맨 아래로 내려 Workflow permissions 섹션을 찾습니다.
  4. Read and write permissions를 선택하고 Save 버튼을 누릅니다. (저장 후 상단에 파란 안내 띠가 뜨고 Save 버튼이 회색으로 비활성화되면 정상 반영된 것입니다.)
  5. 상단 Actions 탭으로 돌아가 실패한 작업 제목을 누르고 우측의 초록색 Re-run jobs 버튼을 누르면 1~2분 내로 초록색 체크(✔)와 함께 배포가 완료됩니다.

문제 2. 배포된 사이트에서 '구글 로그인' 팝업이 떴다가 즉시 사라질 때

원인과 해결 절차 (Firebase 승인된 도메인 추가)

새로 배포된 웹 주소(예: 사용자계정.github.io)가 Firebase 보안 방화벽에 등록되지 않아 차단된 현상입니다. 웹 기반 Build Mode 에이전트는 사용자의 Google Cloud 보안 콘솔을 임의로 조작할 권한이 없으므로, 이 설정은 반드시 사용자가 직접 콘솔에서 1회 추가해야 합니다.

  1. Firebase Console (console.firebase.google.com)에 접속하여 연결된 프로젝트(우측에 AI Studio 배지가 붙은 프로젝트)를 선택합니다.
  2. 왼쪽 메뉴에서 빌드(Build) > Authentication(인증)을 클릭합니다.
  3. 상단 탭에서 설정(Settings)을 누르고 왼쪽 목록의 승인된 도메인(Authorized domains)을 클릭합니다.
  4. 우측의 도메인 추가(Add domain) 버튼을 누르고 배포된 도메인(앞의 https://와 뒤의 하위 경로를 뺀 순수 도메인, 예: 내아이디.github.io)만 입력한 뒤 저장합니다.
  5. 배포된 웹페이지를 새로고침(F5)하면 구글 로그인이 정상 작동합니다.

문제 3. 배포 후 음악(MP3)이나 이미지가 나오지 않고 먹통일 때

원인과 해결 절차 (하위 경로 Base URL 반영)

GitHub Pages는 루트(/)가 아니라 https://계정.github.io/저장소이름/ 형태의 하위 경로에서 실행됩니다. 코드에서 음악을 /musics/bgm.mp3처럼 절대 경로로 부르면 엉뚱한 위치에서 파일을 찾다가 404 에러가 발생합니다. 

[오디오·이미지 먹통 해결용 프롬프트]
GitHub Pages 하위 경로 배포 환경에서 음악 재생이 작동하지 않습니다.
기존 로그인 및 모든 기능 코드는 단 한 줄도 생략하지 말고 그대로 보존한 채 아래 항목만 수정해 주세요.

1. 모든 음원 파일이 빌드 시 누락되지 않도록 `public/musics/` 경로에 배치해 주세요.
2. vite.config.ts의 base 설정을 확인하고, 오디오 경로 호출 시 `import.meta.env.BASE_URL` 또는 상대 경로(`./musics/...`)를 사용하여 서브 경로에서도 404 에러 없이 재생되도록 수정해 주세요.
G10

언제 IDE로 옮기고 어떻게 역할을 나누는가

작은 프로토타입에서 장기 프로젝트와 다중 Agent 협업 환경으로 넘어가는 기준입니다.

G10-01. 웹 빌더에서 로컬 IDE(Antigravity)로 옮겨야 하는 4가지 신호

1

결과물을 일회성으로 끝내지 않고 오랫동안 계속 업그레이드할 때

수개월 이상 기능을 덧붙여야 하는 프로젝트는 내 PC 폴더와 Git 이력으로 정밀하게 관리해야 합니다.

2

작은 수정 하나를 시켰는데 멀쩡하던 다른 기능이 자꾸 깨질 때

Build Mode의 '파일 전체 덮어쓰기(Full Rewrite)' 한계에 도달했다는 신호입니다. 차분 패치(Diff)를 쓰는 IDE로 옮기면 즉시 해결됩니다.

3

숨겨야 할 비밀 키(.env)가 많거나 내 PC의 음악·영상 파일에 의존할 때

로컬 폴더에 파일을 직접 넣어 관리하고 .gitignore로 비밀 파일을 통제하는 것이 훨씬 빠르고 안전합니다.

4

실행해 보고 오류를 고치는 반복 테스트 주기가 짧고 빈번할 때

로컬 개발 서버와 내장 터미널을 통해 변경 사항을 1초 만에 확인하며 반복 검증할 수 있습니다.

G10-02. Vibe Agent와 Coding Agent의 역할 분리

Vibe Agent (Gemini 웹앱)
  • 사용자와의 대화로 모호한 아이디어를 명확한 요구사항과 검수 기준(A01~A19 등)으로 구체화합니다.
  • Coding Agent가 제출한 기획안과 완료 보고서가 원래 의도에 맞는지 1차 검수합니다.
Coding Agent (Build Mode / Antigravity IDE)
  • 합의된 요구사항 문서를 바탕으로 실제 파일 구조를 설계하고 코드를 구현·테스트합니다.
  • Antigravity IDE 안에서는 기본 Agent뿐만 아니라 Claude Code, Codex 확장 및 CLI를 함께 연결해 협업시킬 수 있습니다.
기억은 대화가 아니라 기록 파일에 남긴다: 대화가 길어지면 어떤 AI든 앞선 디테일을 잊습니다. 확정된 요구사항(OWNER_REQUIREMENTS.md)과 현재 진행 상태(STATE.md)를 프로젝트 폴더에 파일로 저장해 두고 Agent들이 읽게 하면 어떤 도구를 쓰든 일관된 품질을 유지할 수 있습니다.

오해를 막는 핵심 Q&A 10선

혼자 실습할 때 가장 자주 헷갈리는 핵심 질문과 명쾌한 해답입니다.

Q1. AI Studio의 Playground와 Build Mode는 무엇이 다른가요?
Playground는 프롬프트 실험과 단일 HTML 파일 생성용 실험실이고, Build Mode는 여러 파일로 구성된 실제 프로젝트 폴더와 백엔드(Firebase), 원클릭 배포까지 수행하는 소프트웨어 공방입니다.
Q2. Build Mode에서 만든 프로젝트 전체를 내 PC로 바로 다운로드할 수 있나요?
네, 가능합니다. 상단 Export > Download as .zip file을 누르면 GitHub를 거치지 않고도 전체 파일이 내 PC에 압축 파일로 즉시 다운로드됩니다.
Q3. Google Cloud에 배포(Publish)해 두면 원본 코드도 그곳에 안전하게 보관되나요?
아닙니다. 클라우드 배포는 실행용 번들만 올려두는 것이므로 원본 코드를 열어 고칠 수 없습니다. 원본 보존을 위해서는 반드시 ZIP 다운로드나 GitHub 푸시를 병행해야 합니다.
Q4. Cloud Run 배포는 2번까지만 무료이고 그다음부터는 막히나요?
카드 미등록 상태(Starter Tier)에서만 최대 2개 앱으로 제한됩니다. 결제 카드를 등록한 Google Cloud 프로젝트를 연결하면 개수 제한이 해제되며, 월 200만 회 요청까지 무료 할당량이 제공됩니다.
Q5. 왜 Build Mode에서 기능 하나를 고쳐달라고 하면 멀쩡하던 다른 기능이 깨지나요?
Build Mode는 수정 시 파일 전체를 1번 줄부터 끝까지 새로 덮어쓰기(Full Rewrite) 때문에 긴 파일에서 기존 코드를 일부 생략하는 실수가 발생할 수 있습니다. 이때가 차분 패치(Diff)를 쓰는 Antigravity IDE로 넘어갈 시점입니다.
Q6. Antigravity IDE를 쓰려면 개발자처럼 코딩과 터미널 명령어를 다 배워야 하나요?
아닙니다. Build Mode와 똑같이 에이전트 채팅창에 말로 지시하여 바이브코딩을 진행합니다. 음악이나 사진 파일을 내 폴더에 마우스로 끌어다 놓고 말로 시킬 수 있어 오히려 파일 다루기가 더 직관적입니다.
Q7. GitHub에 비공개(Private)로 올리는데도 API 키 경고가 뜨며 차단되는 이유는 무엇인가요?
GitHub의 Push Protection 기능은 비공개 저장소라도 코드 안에 실제 API 키가 적혀 있으면 유출 방지를 위해 차단합니다. 화면에 API 키 설정 입력창을 만들거나 .env 파일로 분리해 해결합니다.
Q8. 배포 후 구글 로그인 창이 떴다가 바로 꺼지는 건 AI에게 고쳐달라고 하면 되나요?
코드 문제가 아니라 Firebase 보안 방화벽 설정 문제이므로 사용자가 직접 Firebase Console의 Authentication > Settings > 승인된 도메인에 배포 도메인(예: 계정.github.io)을 등록해야 합니다.
Q9. Antigravity IDE를 설치하면 AI 모델이 내 컴퓨터 안에서 돌아가나요?
아닙니다. 모델의 추론(생각)은 여전히 Google Cloud에서 이루어지며, 내 컴퓨터에서 실행되는 것은 파일 읽기·쓰기, 로컬 서버 구동, 터미널 명령 같은 작업 도구들입니다.
Q10. AI가 만든 프로그램의 오류나 보안 문제에 대한 최종 책임은 누구에게 있나요?
요구사항을 정의하고 결과를 검수하며 최종 배포·공개를 승인하는 Owner(사용자 본인)에게 있습니다. 공개 전 반드시 민감 정보 제외 여부와 핵심 검수 기준을 직접 확인해야 합니다.
